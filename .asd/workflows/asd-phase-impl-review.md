# ASD Workflow: Impl Review

Owner: inline orchestrator; dispatches the internal reviewers of the frozen workflow's `reviewers.impl`, External Review, `asd-tester`, a memory-fix owner and `asd-advisor` for an escalation consult (`agent-protocol.md` "Relay").

## Entry
```json
{"requires": ["active sprint at .asd/sprints/<NNN-slug>/", "clean worktree at phase entry (sprint-lifecycle.md impl-review contract, sole SSoT): after committing a dirty timing ledger and before any dispatch, git status --porcelain; non-empty → FAILED naming the dirty paths; measured once, before step 1", "wave shape: a reviews.impl without waves (legacy flat node) is rewritten inline as {wave: 1, waves: [<that node>]} before anything below reads it (sprint-lifecycle.md 'Review iteration counters' legacy shape); below, K = reviews.impl.wave, the wave node = reviews.impl.waves[K-1], n = waves.length, <id> = this iteration's wave-<K>/iter-NN", "impl-test COMPLETED with a green impacted-set run (sprint-lifecycle.md 'Impacted test set'); state.json.phase advanced from impl-test", "first entry (after initial impl): all plan.md Task checkboxes ticked; impl assessment approved", "cycle re-entry (after impl review-fix + impl-test): review_fixes_pending cleared by impl fix-mode finalize; test_defects_pending null; test-plan.md Suite run records a pass"], "ops": ["context: node .asd/runtime.js context --phase impl-review --role orchestrator at entry, read it; --role <agent> before each agent delegation in ## Dispatch, passed as inputs.context, each Conditional grant whose condition holds named in inputs; --out per agent-protocol.md 'Dispatch payload'", "append friction: F-N to <sprint>/friction-log.md per sprint-lifecycle.md 'Friction log'", "timing: a review-iteration op from step 2 to step 8's (or step 10's) resolution; a dispatch op around each agent delegation in ## Dispatch, re-runs included, External Review's of kind external-review; step 9's tester payload timing key carries <sprint>/timing.jsonl and its dispatch id, the suite ops' --parent (sprint-lifecycle.md 'Operation timing')"]}
```

## Inputs
```json
[".asd/project/config.yaml", "<sprint>/state.json", "<sprint>/plan.md", "<sprint>/test-plan.md", "code + tests diff", "persistent docs per sprint-lifecycle.md 'Input sources'", ".asd/project/stubs.md", "custom-common-rules.md, custom-coding-rules.md", "review files"]
```

## Steps

impl-review fixes no CODE finding itself — those route to impl review-fix mode, followed by impl-test. Exceptions, fixed in place: step 8's minor test-only findings and a test defect step 9 surfaces, both by `asd-tester`; an agent-memory finding (step 8) or memory-caused step 9 red, by its owner's memory-fix (`review-policy.md` "Memory-fix dispatch"); step 9 re-runs after a red fix; a code defect always exits the phase to `impl` test-fix mode.

1. Read `.asd/project/config.yaml` (`review.external_review`, `review.iterations_low/medium/high/critical`, `backward_compat`, `self_hosting`, `language.chat`, `language.docs`); read `<sprint>/state.json` frozen `documents.prd` and `workflow`, and that workflow's definition `.asd/workflows/<workflow>.json` (`sprint-lifecycle.md` "Workflows"). Diff pathspec and payload scope: consumer mode per `external-review.md`'s consumer row; `self_hosting: enabled` per its self-hosting row (the whole repo, excluding `.asd/project/**`/`.asd/sprints/**`/generated views), and adds `--self-hosting` to step 6's `emit-manifest`. At the division point, step 1c runs first. Scope of wave K's iteration NN (the wave node's `iteration` + 1): `sprint-lifecycle.md` "Review iteration counters" "Scope per iteration" (sole SSoT). Diff source (run command): `git diff <from>...HEAD <pathspec>`, `<from>` per bullet; each list is derived by running the diff above as `git -c core.quotePath=false diff --name-only`, one unquoted path per line, so a non-ASCII path still matches as a literal pathspec, and written to a scratch file — the single source of step 6's `emit-manifest` inputs, External Review's included:
   - iteration 1 — the files `<from>...HEAD` changes, `<from>` = wave K−1's last `iteration_heads` sha (wave 1: none), then `node .asd/runtime.js wave-files --waves <sprint>/reviews/impl/waves.json --wave <K> --head <git rev-parse HEAD> [--files <those files>] --out <scratch file>` writes the one list: wave K's list at its current paths, unioned with them; **range base** `<base_branch>`, so the whole list is diffed over `<base_branch>...HEAD`;
   - iteration NN ≥ 2 — range base = `<from>` = the wave node's `iteration_heads["iter-(NN-1)"]` (every commit since the previous iteration started, not just the last). Absent-key fallback: `sprint-lifecycle.md` "State recovery" (sole SSoT).
1a. Before External Review diff assembly/dispatch, run `node .asd/runtime.js external-preflight --input <path>`, `cachePath` set to the canonical path from `external-review.md` "Detection and negative cache" (sole SSoT — not restated here). Local readiness is not model access. Record a transparent availability skip only when unavailable (`external-review.md` "Outcome contract"); real authentication/quota/reachability/command failures are recorded through `external-record-failure` using its fingerprint and the same cache path.
1b. When `review.external_review=enabled`, External Review's `files[]` = step 1's scope file list, unioned at iteration 2+ with the same wave's previous iteration's `Unreviewed files` (`external-review.md` "Iteration semantics"). 1a ready → emitted at step 6. 1a non-ready → nothing is emitted or dispatched; that `files[]` is the skip's `Unreviewed files`.
1c. **Division** — at the division point only (`reviews.impl.waves[0].iteration` 0); wave count, grouping rule and what `review-waves` accepts: `sprint-lifecycle.md` "Review iteration counters" (sole SSoT). Derive the `<base_branch>...HEAD` list as step 1 does and run `node .asd/runtime.js review-waves --files <list> --base <base_branch> --head <git rev-parse HEAD>`; its `waves` is n (`lite`: add `--single` to both runs, so n = 1 and the one list is the whole scope). Group the list into n waves (an empty list: `[[]]`), write them as a JSON array of n path arrays to a scratch file, and re-run adding `--division <that file> --out <sprint>/reviews/impl/waves.json` — for every n, 1 included; a rejection → regroup. Then write inline `reviews.impl` = `{wave: 1, waves: [n t_state.json seed nodes]}`; n > 1 → one decisions-log entry naming n, the measured `lines`, `files` and `bytes` and each wave's theme.
2. **Inline** — set phase; in the wave node, increment `iteration` and record `iteration_heads["iter-NN"]` = `git rev-parse HEAD`. The return's `WAVE` is the wave the entry ends on, `ITER` that wave's counter.
3. Compute severity floor and iteration cap per `review-policy.md` "Iteration severity floor" on wave K's `iteration − A`, A its amendment floor base (`sprint-lifecycle.md` "Review iteration counters")
4. Create folder `<sprint>/reviews/impl/<id>/` if absent
5. **Diff-scoped fan-out** — two skip predicates, evaluated by step 6's `emit-manifest` from the iteration's **file list only** (step 1's scope file list — "the scope list" below); NEVER from `documents.*` (`review-policy.md` "DoD per review phase"). Their member lists live only in `.asd/runtime.js` (`isUiSurface`, `isExecutable`, `NA_TARGETS`); their `n/a` text is owned by `NA_PREDICATES` there, and any canon quote of it must match. A `true` predicate degrades the affected rubric section to `n/a` — in `asd-reviewer-combined` too, whose manifest composes those rubrics — never the agent's dispatch: **the reviewers carrying those rubrics (`asd-reviewer-quality` and `asd-reviewer-efficiency`, or `asd-reviewer-combined`) are always dispatched at step 6, every iteration, unconditionally.**
   - **UI-surface predicate — Quality's UI conformance section n/a'd** only when **no file in the scope list is a UI surface** (`isUiSurface` decides which files qualify; a framework template among them is reviewed under `asd-reviewer-quality.md`'s reduced/carve-out rubric, never n/a'd). Re-evaluated every iteration, never cached.
   - **Perf predicate — Efficiency's five performance sections n/a'd** only when **both** (a) `.asd/project/custom-coding-rules.md` (passed via `--custom-rules`) has no perf-budgets section **and** (b) the scope list contains no executable file (`isExecutable`).
   - The evaluated predicate result reaches each affected reviewer as its manifest's `n_a` entry for that section (`## Rules`). No separate `state.json` value is written for a section skip — only the reviewer's overall verdict token is recorded, at step 8.
6. **Parallel dispatch** — every reviewer delegated to as a **fresh agent** each iteration (clean-context dispatch per `review-policy.md`); no reviewer reused across iterations:
   - **Emit manifests** — for each internal reviewer not latch-skipped (filter below), run `node .asd/runtime.js emit-manifest --reviewer <name> --phase impl-review --files <step 1 scope file list> --out <sprint>/reviews/impl/<id>/ --custom-rules .asd/project/custom-common-rules.md,.asd/project/custom-coding-rules.md --test-plan <sprint>/test-plan.md[,<each test-plan.entry-NN.md segment>] --base <step 1 range base> --head <the wave node's iteration_heads["iter-NN"]>`. It builds that reviewer's own file list (`review-policy.md` "Reviewer responsibility") and writes `<reviewer>.manifest.json` plus its list's `<fingerprint>.diff`. For External Review (step 1b ready, not latch-skipped) run it with `--reviewer external --iteration <NN> --wave <K>` and the same `--files`/`--out`/`--base`/`--head`, without `--custom-rules`/`--test-plan`, plus `--full-files <the carried-over Unreviewed files> --full-base <base_branch>` at iteration 2+ when any are carried over: it writes `external.scope.json` plus its `<fingerprint>.diff` (`external-review.md` "Phase-scoped payload"). The output names each written path.
   - **APPROVE latch filter first** (`sprint-lifecycle.md` "APPROVE latch" — sole SSoT for the mechanism): read the wave node's `latched`; a reviewer key present there is skipped entirely this iteration — no fresh agent call, no new review file, no ledger gate at step 7 for it. The latch is the only agent-level skip. Every key of the definition's `reviewers.impl` NOT latch-skipped is always dispatched to its agent (`## Dispatch`); `external` only if `review.external_review=enabled`, with phase=`impl-review`
   - payloads per `agent-protocol.md` "Dispatch payload", role keys per `## Dispatch`. Internal reviewer (a latch-skipped one receives no dispatch, hence no payload): `manifest` (every id it must cover in its `review-policy.md` coverage ledger, `n/a` authorizations included) and `diff` — the hand-off per `review-policy.md` "Scope hand-off"; `wave` K, `iteration` NN; `out_dir` `<sprint>/reviews/impl/<id>/`; `return_file` `.asd/tmp/<NNN-slug>-impl-wave-<K>-iter-NN-<reviewer>.return.md` (`review-policy.md` "Coverage ledger" Persistence; `<id>`'s `/` written `-`); `floor`; `inputs` (context paths, `<sprint>/test-plan.md` included); `language` (`language.chat`, `language.docs`). No authoring rationale, no prior-iteration verdicts; `interrupted` is set only on a step-7a re-dispatch: that reviewer's interrupted-attempt record for this iteration, count and cause rebuilt from `decisions-log.md` (`review-policy.md` "Clean-context review iteration"); the incremental diff scopes the *input*, not the reviewer's context. `asd-external-review`: `manifest` its `external.scope.json`, `diff` (same hand-off), `out_dir`, `floor`, `inputs` (the reference paths from `external-review.md`'s consumer/self-hosting row), `preflight` (step 1a's result, its `platform` included), `language`; on the wave's iteration ≥ 2 also `findings` per `external-review.md` "Stalemate detection"
   - each return (`## Rules`) is persisted to `<sprint>/reviews/impl/<id>/<reviewer>.md` by step 7's `persist-review`; the commit carrying it also carries any agent memory that reviewer authored (`git-strategy.md` "Commit before review")
7. Wait REVIEW_DONE; run `node .asd/runtime.js persist-review --phase impl --reviewer <key> --in <that reviewer's return file; External Review: its returned text, written to a scratch file> --out-dir <sprint>/reviews/impl/<id>/` — the sole write of `<reviewer>.md` and `<reviewer>.findings.json`, never re-authored by hand (`review-policy.md` "Coverage ledger" Persistence). Exit 2 writes nothing: no verdict token, or any External Review failure (`external-review.md` "Outcome contract") → step 7a's interrupted path; an internal reviewer's ledger failure earns one transcription, re-run on the transcribed text per `review-policy.md` "Coverage ledger" enforcement — passing, the deviation is appended to `<sprint>/friction-log.md`; any other failure, or a failing re-run, rejects and re-dispatches fresh. A dispatched manifest is never re-stamped, by this workflow either: correcting one re-emits it and re-dispatches fresh (`review-policy.md` "Coverage ledger" immutability).
7a. **Interrupted dispatch** — `review-policy.md` "Interrupted dispatch" is the sole SSoT for the durable record, the escalation and the correlated branch, not restated here; its `<id>` is this iteration's. The step header carries no reach; each branch below states its own.
   - Interrupted dispatch — reaches any dispatch, External Review included, per `external-review.md` "Outcome contract": takes the same reject-and-re-dispatch-fresh path as a failed validation above, never that step's transcription branch; a second consecutive interruption on the same manifest → escalation consult, then request user decision per that section's Escalation (retry fresh / abort), never a split.
   - Late duplicate return — reaches any replaced dispatch, External Review included, per `review-policy.md` "Late duplicate return" (sole SSoT for the admission test and every action it mandates). Phase bindings: a return delivering after step 8 recorded its replacement's verdict, once admitted, is persisted by step 7's `persist-review` plus `--late` to `<reviewer>.late.md` in the replaced dispatch's iteration dir (`<sprint>/reviews/impl/<id>/`), linked from `<reviewer>.md`, and carries that section's `verdicts["iter-NN"]`, `latched` and decisions-log writes even though step 8 already ran — for a closed wave, its `.late.md` goes to this iteration's `<sprint>/reviews/impl/<id>/` instead, `--manifest` naming the closed wave's manifest, and its finding joins step 8's unresolved set.
8. Parse first-line verdict tokens from all written reviewer files; write the wave node's `verdicts["iter-NN"]` (keyed by `reviewers.impl`) and `latched` per `sprint-lifecycle.md` "APPROVE latch" — sole SSoT for the every-reviewer-gets-an-entry invariant, the inherited `APPROVE` a latch-skipped reviewer receives and the bare-`APPROVE`-only latch condition; not restated here. Phase bindings: an interrupted attempt contributes no entry, its attempts already logged at step 7a. External Review's availability skip is recorded as `"APPROVE (skipped: <reason>)"` when the phase-supplied preflight returns non-ready; its `external.md` (the `Unreviewed files` line from step 1b included) is persisted through step 7's `persist-review` per `review-policy.md` "Coverage ledger" Persistence, its other duties `external-review.md` "Detection and negative cache"'s, not this step's. Aggregate per `sprint-lifecycle.md` "State recovery" satisfied-vs-blocking semantics, reading `verdicts["iter-NN"]` alone, except per `sprint-lifecycle.md` "State recovery" "User-resolved findings". Fixes route to impl phase (fix mode):
   - **Reviewer questions first** [GATE hard: reviewer question] — a report carrying `question:` items under `## Escalations` (`review-policy.md` "Gate Verdict Format" question carrier) is verdict-bearing, never interrupted (step 7a): escalation consult, then request user decision per item, append the answers to decisions-log, and write each under its item in that reviewer's file per that carrier, so review-fix reads it with the findings
   - **Any FAIL** [GATE hard: review FAIL escalation] → impl-review owns review escalation:
     - parse FAIL findings; group by escalation cause (concept / requirement / contract change; new abstraction; scope expansion; complexity increase)
     - escalation consult, then request user decision in `language.chat`: present each FAIL using Complication Approval format from `core.md`; collect decisions
     - External Review's stalemate FAIL (`Stalemate:` block, `external-review.md` "Stalemate detection") → escalation consult, then request user decision; options and routing per that section, instead of the accept/override bullets below
     - on override → record that finding resolved (`sprint-lifecycle.md` "State recovery" user-resolved findings); exclude from fix set
     - on accept → keep finding in fix set; note approved change in its reviewer file
     - then continue to routing below with surviving findings
   - **Memory findings** — each surviving finding located in `.claude/agent-memory/<owner>/`, plus each `memory-check` hit of step 7's commit, goes to its owner's memory-fix dispatch per `review-policy.md` "Memory-fix dispatch", its `resolved: <ids> — memory-fix, <YYYY-MM-DD>` lines included, before the bullet below tests its predicate, so it never blocks it.
   - **Minor test-only findings** — `review-policy.md` "Minor test-only findings" is the sole SSoT for the condition and the fix; test it on the surviving findings, read from this iteration's `*.findings.json` (step 7). Fires → delegate them to a fresh `asd-tester`, unrouted (`providers.md` "Task-class variants and routing"), its `route <ids>: standard, dispatch HEAD <sha>` decisions-log line appended at the dispatch, payload per `agent-protocol.md` "Dispatch payload", to fix and commit in place (`## Rules`); on its COMPLETED append `resolved: <ids> — test-fix, <YYYY-MM-DD>`, naming only the findings it reports fixed, to each affected reviewer file (`sprint-lifecycle.md` "State recovery" "User-resolved findings"); any finding left, or the branch not firing, falls to the bullet below.
   - **Any unresolved finding remains** (CONCERNS findings, FAIL findings user accepted for fix, and any closed-wave late finding admitted at step 7a) → route to impl review-fix mode (the sprint returns here via impl-test, re-entering wave K) — step 9 is skipped, reviewer DoD was not met:
     - write `state.json.review_fixes_pending = "<id>"` and the decisions-log entry inline.
     - emit phase COMPLETED with `NEXT: impl`
   - **Otherwise — all APPROVE or latched**, or escalation left zero unresolved findings (all FAIL overridden, no CONCERNS) → wave K's roster met (`sprint-lifecycle.md` "Review iteration counters" lifecycle): K < n → write `reviews.impl.wave` = K+1 inline and return to step 1 for wave K+1's iteration 1 in this same entry, no `impl`/`impl-test` between; K = n → reviewer DoD met → proceed to step 9
9. **Terminal full-suite gate** — dispatched only when step 8 (or step 10's cap-accept branch) reaches reviewer DoD met on the last wave; skipped entirely on any route to impl review-fix mode. Delegate to a fresh `asd-tester` for each terminal suite run, unrouted per `providers.md` "Task-class variants and routing", its route line appended at each dispatch as above, payload per `agent-protocol.md` "Dispatch payload" — the phase's only suite runner; with step 8's test-fix and the memory-fix dispatches (steps 8, 9), the phase's only dispatches that change the repo. It runs the sprint cycle's one full-suite run per `## Rules`. Verdict from the runner's exit code plus report, never an agent's summary:
   - **Green** [GATE adaptive: impl-review green handoff] → DoD met: append the decisions-log, clear `review_fixes_pending` inline, apply the green-handoff gate policy, emit the definition's non-`impl` `next["impl-review"]` target — `NEXT: cleanup` (standard) or `NEXT: design-promote` (lite).
   - **Red, test defect** (bad assertion, wrong fixture, flaky pattern) → write inline (mechanical, no gate) clear `state.json.reviews.design.latched` and every impl wave node's `latched` to `{}` sprint-wide (`sprint-lifecycle.md` "APPROVE latch" red-full-suite invalidation; a no-op if already cleared this red event) — then the tester fixes and commits the test (`## Rules`) and this step re-runs as a new terminal run, with its own id on the route line per `providers.md` "Task-class variants and routing"; loop until green or an unfixable state surfaces as `FAILED`
   - **Red, memory-caused** (the failure traces to text in `.claude/agent-memory/<owner>/`) → clear latches as above, then its owner's memory-fix per `review-policy.md` "Memory-fix dispatch", never a `D-N`, and this step re-runs as a new terminal run, dispatched as the test-defect re-run is
   - **Red, code defect** → the pending `D-N` recorded (`## Rules`), write inline `state.json.test_defects_pending = true`, clear latches as above and append the routing log; emit `NEXT: impl` (test-fix mode).
   - several kinds present → fix the test and memory defects first (sub-bullets above), re-run, then route the remaining code defects back per the code-defect sub-bullet
10. Iteration cap reached [GATE hard: review-cap override] (step 3's cap: wave K's next `iteration − A` would exceed all severity-tier budgets per `review-policy.md`; the cap is per wave) — checked when step 8 would route to impl review-fix mode:
    - escalation consult, then request user decision: override cap and continue / accept current findings / abort sprint
    - on override → route to impl review-fix mode; the orchestrator sets `review_fixes_pending` = `<id>` inline.
    - on accept → record every open finding resolved (`cap-accept`, same home); wave K's roster met by cap-accept → as step 8's roster-met branch (next wave, or step 9 when K = n); the COMPLETED note folds in "iteration cap reached in wave K, user accepted"
    - on abort → emit ABORT
11. Any reviewer, `asd-tester` or memory-fix owner FAILED → escalation consult, relay, halt; ABORT → relay, halt; `asd-tester` `QUESTION` → escalation consult, then `agent-protocol.md` "Relay"; a reviewer never returns a bare `QUESTION` (step 8)
12. On `ADVICE_NEEDED` from `asd-tester` → relay per `agent-protocol.md` "Relay"; execution resumes, no halt. A reviewer never emits it.

## Rules
- must (reviewer): for a section its manifest marks `n_a`, never load that domain's inputs; record it `n/a: <predicate>` in the returned section-coverage ledger and still emit one verdict token covering whatever was reviewed.
- must (reviewer): return findings + complete coverage ledger (file, rule and section) + verdict as final text per `t_review.md` (External Review: `external-review/t_review-report.md`), first line `[REVIEW-impl-<reviewer>]: APPROVE|CONCERNS|FAIL`; an internal reviewer also writes it verbatim to its `return_file`. never: write `<reviewer>.md` — step 7 persists it.
- must (reviewer): put a question as a `question:` item under `## Escalations` (`review-policy.md` "Gate Verdict Format"), which makes the report at least CONCERNS; never a bare `QUESTION`, never `ADVICE_NEEDED`.
- must (reviewer): `quality` and `combined` trace AC-N against the `requirements` input (`sprint-lifecycle.md` "Input sources") and read `<sprint>/test-plan.md` with its segments from their manifest; `combined` does both in one pass over the rubrics its manifest composes, step 5's predicates included.
- must (tester, step 8 test-fix): fix and commit in place per `review-policy.md` "Minor test-only findings", reporting each finding fixed or unfixed.
- must (tester, step 9): fresh for each terminal run, never resumed from `impl-test` or an earlier run; run `test` **unscoped** — the sprint cycle's one full-suite run, never the impacted set (`sprint-lifecycle.md` "Impacted test set") — then `lint` and `build` per `commands.yaml`; write the raw result into `test-plan.md`'s `Suite run` section including `HEAD` (current `git rev-parse HEAD`), overwriting the impacted-run record `impl-test` left there; bracket each run with a `suite` op (`scope=full`, `--parent` its dispatch id).
- must (tester, step 9 red): a test defect → fix only the test, never code, and **commit the fix** (Conventional Commits, `git-strategy.md` "Commit before review"; its `impl-review <id> suite` trailer per "Commits") before the re-run — an uncommitted fix would leave `Suite run`'s `HEAD` predating it and the `pr`-phase skip check blind to it; a memory-caused failure → reported with its path, never a `D-N`; a code defect → a pending `D-N` row in `test-plan.md` `Defects`; an unfixable state → `FAILED`.

