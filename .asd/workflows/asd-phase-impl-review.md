# ASD Workflow: Impl Review

Orchestration body for the `asd-phase-impl-review` skill. Operation-mapping to host tools: `.asd/rules/providers.md`.

## Preconditions
- Active sprint at `.asd/sprints/<NNN-slug>/`
- **Clean worktree at phase entry** (`sprint-lifecycle.md`'s impl-review contract, sole SSoT): after committing a dirty timing ledger and before any dispatch, run `git status --porcelain`; non-empty output → `FAILED`, naming the dirty paths. Measured once, at entry, before step 1.
- **Wave shape at entry**: a `reviews.impl` without `waves` (legacy flat node) is rewritten inline as `{wave: 1, waves: [<that node>]}` before anything below reads it (`sprint-lifecycle.md` "Review iteration counters" legacy shape). Below, K = `reviews.impl.wave`, "the wave node" = `reviews.impl.waves[K-1]`, n = `waves.length`, `<id>` = this iteration's id `wave-<K>/iter-NN`.
- impl-test COMPLETED signal received with a green impacted-set run (`sprint-lifecycle.md` "Impacted test set"); `state.json.phase` advanced from `impl-test`
- **First entry** (after initial impl): all plan.md Task checkboxes ticked; impl assessment approved
- **Cycle re-entry** (after impl review-fix + impl-test): `state.json.review_fixes_pending` cleared by impl fix-mode finalize; `test_defects_pending` null; `<sprint>/test-plan.md` `Suite run` records a pass

## Operations used
- read: `.asd/project/config.yaml`, `state.json`, plan.md, `test-plan.md`, code + tests diff, persistent docs, `.asd/project/stubs.md`, `custom-common-rules.md`, `custom-coding-rules.md`, review files
- run command: `git diff` to compute the scope file list (step 1); `commands.yaml` `test`/`lint`/`build`, unscoped, for the terminal full-suite gate (step 9) — dispatched to `asd-tester`, never run by this workflow or a reviewer directly
- write a file: the step 1 list and the step 1c division, to scratch files — the directory `node .asd/runtime.js scratch-dir` prints (`artifact-layout.md` "Scratch directory"); External Review's returned text, to a scratch file for `persist-review` (step 7) — an internal reviewer writes its own return file; the orchestrator updates state inline
- request user decision: reviewer questions, escalation on FAIL or iteration cap
- delegate to agent in parallel: reviewers; the orchestrator writes state, routing and decisions inline; `asd-tester` runs step 8's test-fix and the terminal full-suite gate.
- append friction: `F-N` entries to `<sprint>/friction-log.md` per `sprint-lifecycle.md` "Friction log"
- timing: per `sprint-lifecycle.md` "Operation timing" — a `review-iteration` op from step 2 to step 8's resolution (or step 10's); `dispatch` ops (`<reviewer key> <id>`; `external-review` kind for External Review) around step 6's reviewers and step 8's and step 9's tester dispatches (re-runs included, routing attrs carried); step 9's tester payload carries `<sprint>/timing.jsonl` and its dispatch id (the `suite` ops' `--parent`) and brackets each run with a `suite` op (`scope=full`); commit a dirty ledger before the entry check

## Workflow

1. Read `.asd/project/config.yaml` (`review.external_review`, `review.iterations_low/medium/high/critical`, `backward_compat`, `self_hosting`, `language.chat`, `language.docs`); read `<sprint>/state.json` frozen `documents.prd` and `workflow`, and that workflow's definition `.asd/workflows/<workflow>.json` (`sprint-lifecycle.md` "Workflows"). Diff pathspec and payload scope: consumer mode per `external-review.md`'s consumer row; `self_hosting: enabled` per its self-hosting row (the whole repo, since everything here IS framework source, excluding `.asd/project/**`/`.asd/sprints/**`/generated views), and adds `--self-hosting` to step 6's `emit-manifest`. At the division point, step 1c runs first. Scope of wave K's iteration NN (the wave node's `iteration` + 1): `sprint-lifecycle.md` "Review iteration counters" "Scope per iteration" (sole SSoT). Diff source (run command): `git diff <from>...HEAD <pathspec>`, `<from>` per bullet; each list is derived by running the diff above as `git -c core.quotePath=false diff --name-only`, one unquoted path per line, so a non-ASCII path still matches as a literal pathspec, and written to a scratch file — the single source of step 6's `emit-manifest` inputs, External Review's included:
   - iteration 1 — the files `<from>...HEAD` changes, `<from>` = wave K−1's last `iteration_heads` sha (wave 1: none), then `node .asd/runtime.js wave-files --waves <sprint>/reviews/impl/waves.json --wave <K> --head <git rev-parse HEAD> [--files <those files>] --out <scratch file>` writes the one list: wave K's list at its current paths, unioned with them; **range base** `<base_branch>`, so the whole list is diffed over `<base_branch>...HEAD`;
   - iteration NN ≥ 2 — range base = `<from>` = the wave node's `iteration_heads["iter-(NN-1)"]` (every commit since the previous iteration started, not just the last). Absent-key fallback: `sprint-lifecycle.md` "State recovery" (sole SSoT).
1a. Before External Review diff assembly/dispatch, run `node .asd/runtime.js external-preflight --input <path>`, `cachePath` set to the canonical path from `external-review.md` "Detection and negative cache" (sole SSoT — not restated here). Local readiness is not model access. Record a transparent availability skip only when unavailable (`external-review.md` "Outcome contract"); real authentication/quota/reachability/command failures are recorded through `external-record-failure` using its fingerprint and the same cache path.
1b. When `review.external_review=enabled`, External Review's `files[]` = step 1's scope file list, unioned at iteration 2+ with the same wave's previous iteration's `Unreviewed files` (`external-review.md` "Iteration semantics"). 1a ready → emitted at step 6. 1a non-ready → nothing is emitted or dispatched; that `files[]` is the skip's `Unreviewed files`.
1c. **Division** — at the division point only (`reviews.impl.waves[0].iteration` 0); wave count, grouping rule and what `review-waves` accepts: `sprint-lifecycle.md` "Review iteration counters" (sole SSoT). Derive the `<base_branch>...HEAD` list as step 1 does and run `node .asd/runtime.js review-waves --files <list> --base <base_branch> --head <git rev-parse HEAD>`; its `waves` is n. Group the list into n waves (an empty list: `[[]]`), write them as a JSON array of n path arrays to a scratch file, and re-run adding `--division <that file> --out <sprint>/reviews/impl/waves.json` — for every n, 1 included; a rejection → regroup. Then write inline `reviews.impl` = `{wave: 1, waves: [n t_state.json seed nodes]}`; n > 1 → one decisions-log entry naming n, the measured `lines`, `files` and `bytes` and each wave's theme.
2. **Inline** — set phase; in the wave node, increment `iteration` and record `iteration_heads["iter-NN"]` = `git rev-parse HEAD`.
3. Compute severity floor and iteration cap per `review-policy.md` "Iteration severity floor" on wave K's `iteration − A`, A its amendment floor base (`sprint-lifecycle.md` "Review iteration counters")
4. Create folder `<sprint>/reviews/impl/<id>/` if absent
5. **Diff-scoped fan-out** — two skip predicates, evaluated by step 6's `emit-manifest` from the iteration's **file list only** (step 1's scope file list — "the scope list" below); NEVER from `documents.*` (preserves `review-policy.md` "DoD per review phase" table note verbatim: "absence of a ux-spec draft never implies absence of UI code to review"). Their member lists live only in `.asd/runtime.js` (`isUiSurface`, `isExecutable`, `NA_TARGETS`); their `n/a` text is owned by `NA_PREDICATES` there, and any canon quote of it must match. A `true` predicate degrades the affected rubric section to `n/a` — in `asd-reviewer-combined` too, whose manifest composes those rubrics — never the agent's dispatch: **the reviewers carrying those rubrics (`asd-reviewer-correctness` and `asd-reviewer-efficiency`, or `asd-reviewer-combined`) are always dispatched at step 6, every iteration, unconditionally.**
   - **UI-surface predicate — Correctness's UI conformance section n/a'd** only when **no file in the scope list is a UI surface** (`isUiSurface` decides which files qualify; a framework template among them is reviewed under `asd-reviewer-correctness.md`'s reduced/carve-out rubric, never n/a'd). Any such file entering the diff — this iteration or a later one — re-includes the section automatically; the predicate is re-evaluated every iteration, never cached. `asd-reviewer-correctness.md`'s carve-out (2) trigger points here rather than restating it.
   - **Perf predicate — Efficiency's five performance sections n/a'd** only when **both** (a) `.asd/project/custom-coding-rules.md` (passed via `--custom-rules`) has no perf-budgets section **and** (b) the scope list contains no executable file (`isExecutable`). Conjunctive — either condition false means the sections are reviewed as normal (three of its remaining rubric items are budget-independent regardless).
   - The evaluated predicate result reaches each affected reviewer as its manifest's `n_a` entry for that section — **the reviewer never loads that domain's inputs for an n/a'd section**. The reviewer records the section as `n/a: <predicate>` in its own returned section-coverage ledger and still emits one verdict token covering whatever it did review. No separate `state.json` value is written for a section skip — only the reviewer's overall verdict token is recorded, at step 8.
6. **Parallel dispatch** — every reviewer delegated to as a **fresh agent** each iteration (clean-context dispatch per `review-policy.md`); no reviewer reused across iterations:
   - **Emit manifests** — for each internal reviewer not latch-skipped (filter below), run `node .asd/runtime.js emit-manifest --reviewer <name> --phase impl-review --files <step 1 scope file list> --out <sprint>/reviews/impl/<id>/ --custom-rules .asd/project/custom-common-rules.md,.asd/project/custom-coding-rules.md --test-plan <sprint>/test-plan.md[,<each test-plan.entry-NN.md segment>] --base <step 1 range base> --head <the wave node's iteration_heads["iter-NN"]>`. It builds that reviewer's own file list (`review-policy.md` "Reviewer responsibility") and writes `<reviewer>.manifest.json` plus its list's `<fingerprint>.diff`. For External Review (step 1b ready, not latch-skipped) run it with `--reviewer external --iteration <NN> --wave <K>` and the same `--files`/`--out`/`--base`/`--head`, without `--custom-rules`/`--test-plan`, plus `--full-files <the carried-over Unreviewed files> --full-base <base_branch>` at iteration 2+ when any are carried over: it writes `external.scope.json` plus its `<fingerprint>.diff` (`external-review.md` "Phase-scoped payload"). The output names each written path.
   - **APPROVE latch filter first** (`sprint-lifecycle.md` "APPROVE latch" — sole SSoT for the mechanism): read the wave node's `latched`; a reviewer key present there is skipped entirely this iteration — no fresh agent call, no new review file, no ledger gate at step 7 for it. Distinct from the section-level n/a mechanism below, which still fully dispatches Correctness/Efficiency; the latch skips the whole agent. Every key of the definition's `reviewers.impl` NOT latch-skipped is always dispatched to its agent (no other agent-level skip):
   - `correctness` → `asd-reviewer-correctness` — AC-N coverage trace vs code/tests uses PRD AC-N if `documents.prd` enabled, else `sprint.md`'s own AC-N; its UI conformance section is n/a per step 5's UI-surface predicate when applicable
   - `efficiency` → `asd-reviewer-efficiency` — its five performance sections are n/a per step 5's conjunctive predicate when applicable
   - `testing` → `asd-reviewer-testing` — `<sprint>/test-plan.md` is its primary input
   - `documentation` → `asd-reviewer-documentation`
   - `combined` → `asd-reviewer-combined` — one pass over the rubrics its manifest composes, step 5's predicates included; AC-N source per `sprint-lifecycle.md` "Workflows"; `<sprint>/test-plan.md` is context, not a manifest file
   - `external`, if `review.external_review=enabled` AND not latch-skipped → `asd-external-review` with phase=`impl-review`
   - every payload below opens with the header per `providers.md` "Dispatch payload header"; payload to each internal reviewer (latch-skipped reviewers receive no dispatch, hence no payload): its emitted **manifest** path (every id it must cover in its `review-policy.md` coverage ledger, `n/a` authorizations included) and that manifest's `.diff` path — the hand-off per `review-policy.md` "Scope hand-off" — wave K and iteration NN, review output dir `<sprint>/reviews/impl/<id>/`, its return file `.asd/tmp/<NNN-slug>-impl-wave-<K>-iter-NN-<reviewer>.return.md` (`review-policy.md` "Coverage ledger" Persistence; `<id>`'s `/` written `-`), severity floor, relevant context paths (`<sprint>/test-plan.md` included), `language.chat`, `language.docs`. Payload carries no authoring rationale, no prior-iteration verdicts; a step-7a re-dispatch additionally carries that reviewer's interrupted-attempt record for this iteration, count and cause rebuilt from `decisions-log.md` (`review-policy.md` "Clean-context review iteration"); incremental diff scopes the *input*, not reviewer's context. Payload to `asd-external-review`: its `external.scope.json` and diff paths (same hand-off), review output dir, severity floor, the reference paths from `external-review.md`'s consumer/self-hosting row, step 1a's preflight result (its `platform` included), `language.chat`, `language.docs`. For `asd-external-review` on the wave's iteration ≥ 2, also pass the finding set per `external-review.md` "Stalemate detection"
   - each reviewer returns its findings + complete coverage ledger (file, rule, and section) + verdict as final text per `t_review.md` (or `external-review/t_review-report.md` for external), first-line verdict token `[REVIEW-impl-<reviewer>]: ...`, an internal reviewer also writing it verbatim to its return file; **this workflow persists that text to `<sprint>/reviews/impl/<id>/<reviewer>.md` through `persist-review`** (step 7) — the reviewer itself performs no write of that file, and the commit carrying it also carries any agent memory that reviewer authored (`git-strategy.md` "Commit before review")
7. Wait REVIEW_DONE; run `node .asd/runtime.js persist-review --phase impl --reviewer <key> --in <that reviewer's return file; External Review: its returned text, written to a scratch file> --out-dir <sprint>/reviews/impl/<id>/` — the sole write of `<reviewer>.md` and `<reviewer>.findings.json`, never re-authored by hand (`review-policy.md` "Coverage ledger" Persistence). Exit 2 writes nothing: no verdict token, or any External Review failure (`external-review.md` "Outcome contract") → step 7a's interrupted path; an internal reviewer's ledger failure earns one transcription, re-run on the transcribed text per `review-policy.md` "Coverage ledger" enforcement — passing, the deviation is appended to `<sprint>/friction-log.md`; any other failure, or a failing re-run, rejects and re-dispatches fresh. A dispatched manifest is never re-stamped, by this workflow either: correcting one re-emits it and re-dispatches fresh (`review-policy.md` "Coverage ledger" immutability).
7a. **Interrupted dispatch** — `review-policy.md` "Interrupted dispatch" is the sole SSoT for the durable record, the escalation and the correlated branch, not restated here; its `<id>` is this iteration's. The step header carries no reach; each branch below states its own.
   - Interrupted dispatch — reaches any dispatch, External Review included, per `external-review.md` "Outcome contract": takes the same reject-and-re-dispatch-fresh path as a failed validation above, never that step's transcription branch; a second consecutive interruption on the same manifest → request user decision per that section's Escalation (retry fresh / abort), never a split.
   - Late duplicate return — reaches any replaced dispatch, External Review included, per `review-policy.md` "Late duplicate return" (sole SSoT for the admission test and every action it mandates). Phase bindings: a return delivering after step 8 recorded its replacement's verdict, once admitted, is persisted by step 7's `persist-review` plus `--late` to `<reviewer>.late.md` in the replaced dispatch's iteration dir (`<sprint>/reviews/impl/<id>/`), linked from `<reviewer>.md`, and carries that section's `verdicts["iter-NN"]`, `latched` and decisions-log writes even though step 8 already ran — for a closed wave, its `.late.md` goes to this iteration's `<sprint>/reviews/impl/<id>/` instead, `--manifest` naming the closed wave's manifest, and its finding joins step 8's unresolved set.
8. Parse first-line verdict tokens from all written reviewer files; write the wave node's `verdicts["iter-NN"]` (keyed by `reviewers.impl`) and `latched` per `sprint-lifecycle.md` "APPROVE latch" — sole SSoT for the every-reviewer-gets-an-entry invariant, the inherited `APPROVE` a latch-skipped reviewer receives and the bare-`APPROVE`-only latch condition; not restated here. Phase bindings: an interrupted attempt contributes no entry, its attempts already logged at step 7a. External Review's availability skip is recorded as `"APPROVE (skipped: <reason>)"` when the phase-supplied preflight returns non-ready; its `external.md` (the `Unreviewed files` line from step 1b included) is persisted through step 7's `persist-review` per `review-policy.md` "Coverage ledger" Persistence, its other duties `external-review.md` "Detection and negative cache"'s, not this step's. Aggregate per `sprint-lifecycle.md` "State recovery" satisfied-vs-blocking semantics, reading `verdicts["iter-NN"]` alone, except per `sprint-lifecycle.md` "State recovery" "User-resolved findings". impl-review does NOT fix findings itself — fixes route to impl phase (fix mode):
   - **Reviewer questions first** — a report carrying `question:` items under `## Escalations` (`review-policy.md` "Gate Verdict Format" question carrier) is verdict-bearing, never interrupted (step 7a): request user decision per item, append the answers to decisions-log, and write each under its item in that reviewer's file per that carrier, so review-fix reads it with the findings (such a report is at least CONCERNS, per that carrier)
   - **Any FAIL** → escalation (impl-review owns review escalation):
     - parse FAIL findings; group by escalation cause (concept / requirement / contract change; new abstraction; scope expansion; complexity increase)
     - request user decision in `language.chat`: present each FAIL using Complication Approval format from `core.md`; collect decisions
     - External Review's stalemate FAIL (`Stalemate:` block, `external-review.md` "Stalemate detection") → request user decision; options and routing per that section, instead of the accept/override bullets below
     - on override → record that finding resolved (`sprint-lifecycle.md` "State recovery" user-resolved findings); exclude from fix set
     - on accept → keep finding in fix set; note approved change in its reviewer file
     - then continue to routing step below with surviving findings
   - **Low-severity test-only findings** — `review-policy.md` "Low-severity test-only findings" is the sole SSoT for the condition and the fix; test it on the surviving findings, read from this iteration's `*.findings.json` (step 7). Fires → delegate them to a fresh `asd-tester`, routed as `asd-phase-impl-test.md` step 1a with its tier per `providers.md` "Task-class variants and routing", its payload opening with the header per `providers.md` "Dispatch payload header", to fix and commit in place per that section; on its COMPLETED append `resolved: <ids> — test-fix, <YYYY-MM-DD>`, naming only the findings it reports fixed, to each affected reviewer file (`sprint-lifecycle.md` "State recovery" "User-resolved findings"); any finding left, or the branch not firing, falls to the bullet below.
   - **Any unresolved finding remains** (CONCERNS findings, FAIL findings user accepted for fix, and any closed-wave late finding admitted at step 7a) → route to impl review-fix mode (the sprint returns here via impl-test, re-entering wave K) — the terminal suite gate (step 9) is skipped, reviewer DoD was not met:
     - write `state.json.review_fixes_pending = "<id>"` and the decisions-log entry inline.
     - emit phase COMPLETED with `NEXT: impl`
   - **Otherwise — all APPROVE or latched**, or escalation left zero unresolved findings (all FAIL overridden, no CONCERNS) → wave K's roster met (`sprint-lifecycle.md` "Review iteration counters" lifecycle): K < n → write `reviews.impl.wave` = K+1 inline and return to step 1 for wave K+1's iteration 1 in this same entry, no `impl`/`impl-test` between; K = n → reviewer DoD met → proceed to step 9 (terminal full-suite gate)
9. **Terminal full-suite gate** — dispatched only when step 8 (or step 10's cap-accept branch) reaches reviewer DoD met on the last wave; skipped entirely on any route to impl review-fix mode. Delegate to a fresh `asd-tester` for each terminal suite run, routed as `asd-phase-impl-test.md` step 1a with its tier per `providers.md` "Task-class variants and routing", its payload opening with the header per `providers.md` "Dispatch payload header", never one resumed from `impl-test` or an earlier run (`sprint-lifecycle.md` "Impl-test phase"; with step 8's test-fix, the phase's only dispatches that change the repo): run `test` **unscoped** — the sprint cycle's one full-suite run, never the impacted set (`sprint-lifecycle.md` "Impacted test set") — then `lint` and `build` per `commands.yaml`; write the raw result into `test-plan.md`'s `Suite run` section including `HEAD` (current `git rev-parse HEAD`), overwriting the impacted-run record `impl-test` left there. Verdict from the runner's exit code plus report, never an agent's summary:
   - **Green** → DoD met: append the decisions-log, clear `review_fixes_pending` inline, apply the green-handoff gate policy, emit the definition's non-`impl` `next["impl-review"]` target — `NEXT: retro` (standard) or `NEXT: design-promote` (lite).
   - **Red, test defect** (bad assertion, wrong fixture, flaky pattern) → write inline (mechanical, no gate) clear `state.json.reviews.design.latched` and every impl wave node's `latched` to `{}` sprint-wide (red-full-suite invalidation, `sprint-lifecycle.md` "APPROVE latch" — every red full suite clears every latch sprint-wide regardless of which triage branch follows; a no-op if the code-defect sub-bullet below already cleared them this same red event) — then `asd-tester` fixes the test in place, **commits the fix** (Conventional Commits, per `git-strategy.md` "Commit before review"; its `impl-review <id> suite` trailer per "Commits") before re-running, and re-runs this step as a new terminal run, routed with its own id per `providers.md` "Task-class variants and routing"; loop until green or an unfixable state surfaces as `FAILED`. Never a code fix — only the test itself. The commit is mandatory before the re-run's `HEAD` is recorded — an uncommitted fix would leave `Suite run`'s `HEAD` predating it and the `pr`-phase skip check blind to it
   - **Red, code defect** → record pending defect, clear latches and append the routing log inline; emit `NEXT: impl` (test-fix mode).
   - both kinds present → fix the test defects first (sub-bullet above), re-run, then route the remaining code defects back per the code-defect sub-bullet
10. Iteration cap reached (step 3's cap: wave K's next `iteration − A` would exceed all severity-tier budgets per `review-policy.md`; the cap is per wave) — checked when step 8 would route to impl review-fix mode:
    - request user decision: override cap and continue / accept current findings / abort sprint
    - on override → route to impl review-fix mode; the orchestrator sets `review_fixes_pending` = `<id>` inline.
    - on accept → record every open finding resolved (`cap-accept`, same home); wave K's roster met by cap-accept → as step 8's roster-met branch (next wave, or step 9 when K = n); the COMPLETED note folds in "iteration cap reached in wave K, user accepted"
    - on abort → emit ABORT
11. Any reviewer or `asd-tester` FAILED / ABORT → relay, halt; `asd-tester` `QUESTION` → per `sprint-lifecycle.md`'s `QUESTION` protocol; a reviewer never returns a bare `QUESTION` (step 8)
12. On `ADVICE_NEEDED` from any dispatched agent → relay per `sprint-lifecycle.md`'s `ADVICE_NEEDED` protocol; execution resumes, no halt.

## Artefacts produced
- `<sprint>/reviews/impl/waves.json` (step 1c, at the division point; overwritten at a re-division)
- `<sprint>/reviews/impl/<id>/<reviewer>.md` and `<reviewer>.findings.json` per dispatched `reviewers.impl` key (step 7's `persist-review`; `external` only when `external_review=enabled`; not written this iteration when latch-skipped — step 6); UI conformance and the five performance sections may be n/a per step 5's diff-scoped fan-out
- `<sprint>/reviews/impl/<id>/<reviewer>.manifest.json` (step 6, per dispatched internal reviewer), `external.scope.json` (step 6, External Review dispatched) and one `<fingerprint>.diff` per distinct list and range
- `<sprint>/reviews/impl/<id>/<reviewer>.late.md` and its `.late.findings.json` (only for a late duplicate return admitted at step 7a; which iteration's `<id>`, and its link, per `review-policy.md` "Late duplicate return")
- Updated `<sprint>/test-plan.md` `Suite run` section (step 9, overwriting the impacted-run record) and, on a code-defect red, a new `Defects` `D-N` row
- `asd-tester` test-fix commits and their `resolved: … — test-fix` lines in the reviewer files (step 8)
- Updated `state.json` (phase; `reviews.impl.wave` and each wave node's `iteration`, `iteration_heads`, `verdicts`, `latched`; `review_fixes_pending`; `test_defects_pending` on a step-9 code-defect red)
- decisions-log entry on a division into n > 1 waves, reviewer-question answers (step 8), DoD met (full suite green), route-to-impl-fix, override, or terminal-suite-red

Note: impl-review fixes no CODE finding itself — those route to the impl phase (review-fix mode) on the next cycle, followed by impl-test. Two exceptions, both `asd-tester` fixing tests in place: step 8's low-severity test-only findings, and a test defect the terminal full-suite gate (step 9) surfaces, re-run after; a code defect never is — it always exits the phase to `impl` test-fix mode.

## Agents delegated to
- The internal reviewers of the frozen workflow's `reviewers.impl` — parallel, dispatched unless APPROVE-latched (step 6); step 5's diff-scoped predicates degrade a Correctness or Efficiency rubric section (composed into `combined` too) to `n/a` for a dispatched reviewer, never skips the agent by itself (step 5) — the latch is the only agent-level skip
- External Review — parallel (when enabled and not latch-skipped)
- `asd-tester` — step 8's low-severity test-only fix and the terminal full-suite gate (step 9, reached only on reviewer DoD met); the phase's sole non-reviewer agent and its only capability to run commands
- The orchestrator owns decisions-log and routing writes; no orchestration agent is dispatched.
- No devs — finding fixes performed by impl phase (review-fix mode)

## Return contract (single line)
```
PHASE: impl-review | SPRINT: <NNN-slug> | WAVE: <K> | ITER: <N> | STATUS: <complete|blocked|aborted> | NEXT: <retro|design-promote|impl>
```
`WAVE` = the wave the entry ended on, `ITER` = that wave's counter.
`NEXT: retro` (standard) or `NEXT: design-promote` (lite) on reviewer DoD met AND terminal full suite green (step 9); `NEXT: impl` when unresolved findings route the sprint to impl review-fix mode, OR when the terminal full suite is red with code defects (test-fix mode).
