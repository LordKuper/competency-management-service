## Contradictions (optional)
- `sprint.md` AC-1 vs `sprint.md` AC-7: AC-1 требует, чтобы при отказе SMTP «инициатор видел понятное сообщение»; AC-7 требует одинакового ответа анонимного «Не помню пароль» для любого e-mail. Сообщение об отказе появилось бы только для существующей активной записи и раскрыло бы её; синхронная отправка ещё и делает время ответа зависимым от существования. Канонической стороны нет; winner=unsettled → user: анонимный запрос всегда получает одинаковый нейтральный ответ, отказ — только в журнале (`Mail.SendFailed`) и логе; сообщение об отказе по AC-1 — только для действий администратора (2026-10-08, AC-1 уточнён).
- `docs/architecture/tech-reference/mailkit-4.18.1.md` («Отправка не блокирует HTTP-запрос: outbox/`BackgroundService`») vs `sprint.md` AC-11 («после действия пользователь видит, что письмо отправлено или не отправлено»): канонический документ ограничивает способ выполнения AC-11; winner=unsettled → user: действия администратора отправляют письмо синхронно после фиксации с коротким таймаутом; анонимный «Не помню пароль» — фоновая очередь в памяти (Channel + BackgroundService, без outbox; потеря при перезапуске pod принята); конвенция `mailkit-4.18.1.md` правится на design-promote (2026-10-08).

Устаревшие формулировки канонических документов, прямо отменённые принятым scope (сброс паролем администратором, «анонимны только пробы и вход», «вне рамок: сброс по e-mail»), — не противоречия, а документы к обновлению на design-promote («Gaps»). Q4 `stack.html` (DataProtection только для cookie и antiforgery) сужает проектные варианты: исключает `DataProtectorTokenProvider`.

## Gaps
- **Одноразовые ссылки.** Механизма нет. `DataProtectorTokenProvider` не подходит: он без состояния и действует, пока совпадает security stamp; отмена прежней ссылки при выдаче новой потребовала бы смены stamp на каждый запрос, и анонимный «Не помню пароль» обрывал бы сессии чужой записи (DoS); смена e-mail stamp не меняет; Q4 ограничивает DataProtection. Предложение: случайный токен ≥ 256 бит, в `users` — только его SHA-256, срок и время выдачи (одна действующая ссылка на запись, назначение — из состояния записи); сравнение в постоянное время или поиск по уникальному частичному индексу; ссылка привязана к security stamp на момент выдачи (её отменяют блокировка, смена пароля, роли, привязки, увольнение), смена e-mail очищает ссылку явно; колонки ссылки не `[Audited]`.
- **Состояние «приглашён».** Минимально — `password_hash IS NULL` (без новой колонки и переноса данных); в ответ и фильтр — новое поле (`isInvited` или `status`), `isBlocked` не трогать; вход приглашённой записи — тот же 401 с `SpendHashingTime` и своей причиной в журнале; задание пароля по приглашению снимает lockout.
- **Последний администратор.** Признак «активный» во всех четырёх местах и в `EmployeeAccounts` дополнить условием «зарегистрирован» (`password_hash IS NOT NULL`), иначе систему можно оставить только с приглашённым администратором, и bootstrap не сработает.
- **Новые методы API.** Анонимные: «Не помню пароль», «задать пароль по приглашению», «задать новый пароль по ссылке» — `.AllowAnonymous()`, ограничение частоты, 400 вместо 401 для недействительной ссылки (иначе SPA уведёт на `/login`). Административные: «Отправить приглашение повторно», «Отправить ссылку для сброса пароля». Удалить `POST /users/{id}/reset-password`, `ResetPasswordRequest`, поле `password` в `CreateUserRequest`; новые типы назвать иначе, чем `ResetPasswordRequest`.
- **Ограничение частоты (AC-7).** По адресу — новая настраиваемая политика по образцу `login` (общий ли счётчик у точек одной политики — проверить в plan); по e-mail — тихий пропуск, если ссылка записи выдана недавно (по времени выдачи в строке), для несуществующих адресов ничего не хранить (разделы по пользовательскому вводу могут исчерпать память); анонимные точки с паролем тоже ограничить (PBKDF2).
- **Транзакции и отправка.** Отправлять только после фиксации, никогда под блокировкой дерева, администраторов или строки (таймаут SMTP под `pg_advisory_xact_lock` остановил бы все изменения оргструктуры); отказ SMTP оставляет запись приглашённой с действующей ссылкой, повторная отправка её заменяет.
- **Блокировки (AC-14).** Операции со ссылкой берут только строку учётной записи (позиция 3 общего порядка); детерминированные тесты гонок: принятие приглашения против повторной отправки, против блокировки; двойное использование токена; сброс против смены своего пароля; последний администратор при приглашённых администраторах.
- **SMTP-транспорт.** Место — `Competency.Platform` (сквозной механизм, §31 Постановки), один конкретный класс без интерфейса; тексты писем и построение ссылок — в `user-management`. Параметры: хост, порт, режим TLS (`SecureSocketOptions`), необязательные логин и пароль, отправитель, таймаут (по умолчанию у `SmtpClient` 2 мин — уменьшить). Проверку конфигурации при старте пропускать в tooling-запуске.
- **Публичный адрес.** Нет настройки (`App:PublicBaseUrl` или аналог) и проверки абсолютного http(s) URL. Токен в ссылке — во фрагменте (`#…`), не в пути и query: не попадает в журналы прокси/Ingress и Referer, не тратится почтовыми сканерами; SPA читает фрагмент, очищает адресную строку (`history.replaceState`), отправляет токен POST; GET токен не тратит. В разработке ссылки ведут на Vite (`http://localhost:5173`), в профиле «API» без Vite они не откроются.
- **Письма.** Русские тема и текст; конвенция «шаблоны в ресурсах» (`.resx`) избыточна для двух писем — поправить на promote. При фоновой обработке: `AuditEntry` нужно необязательное поле request id (аддитивно), `HttpContext` в фоне не использовать.
- **Журнал (AC-10).** Новые действия: `AppUser.InvitationSent` (причина — первичная/повторная), `Auth.RegistrationCompleted`, `Auth.PasswordResetRequested` (актор — администратор или сама запись), `Auth.PasswordResetCompleted`, `Mail.SendFailed` (тип письма, без адреса); изменения — через `Stage`, отправка и отказ — через `WriteAsync` после фиксации; без токенов, ссылок, адресов.
- **Frontend (AC-11).** Три анонимных экрана через `standaloneRoutes`, общая раскладка выносится из `LoginPage`; ссылка «Не помню пароль»; в «Пользователях» — без поля пароля и `ResetPasswordModal`, третье состояние в `UserStatusTag` (в т. ч. «приглашён + заблокирован»), фильтр «Приглашённые», пункты меню по состоянию, результат «письмо отправлено / не отправлено». UX-спецификации новых экранов нет (lite), `docs/ux/user-management.html` обновляется на design-promote.
- **Тесты.** ~48 вызовов `CreateUserAsync` рассчитаны на пароль при создании — вспомогательный метод: создать запись через API и записать `password_hash` напрямую в БД теста (`PasswordHasher`, `InternalsVisibleTo`). Для тестов приглашения и сброса — перехват писем (контейнер Mailpit через ядро Testcontainers или собственная заглушка SMTP). `ApiHost` передаёт параметры SMTP и публичного адреса.
- **Dev и развёртывание (AC-3).** Сервис перехватчика в `deploy/dev/docker-compose.yml` (порты только на `127.0.0.1`, переопределение как `DEV_DB_PORT`); кандидат — Mailpit `axllent/mailpit:v1.31.4` (MIT, Docker Hub 2026-10-03, SMTP 1025, веб 8025). `launchSettings.json` — SMTP перехватчика и публичный адрес; `configmap.yaml` — хост, порт, TLS, отправитель, публичный адрес, сроки ссылок; `secret.template.yaml` и `app.yaml` — `Smtp__UserName`, `Smtp__Password` через `secretKeyRef` с `optional: true`; разделы в `deploy/README.md` и `deploy/dev/README.md`.
- **Правила.** AC-12: заменить раздел целиком; «переиспользуемого скрипта наполнения 10 000+ сотрудников» в репозитории нет — по решению пользователя (2026-10-08) его создаёт первая Task с perf-риском, в этом спринте не создаётся. AC-14: согласован с порядком блокировок `user-management.md`. AC-15: конфликтов нет (`deploy/dev/README.md` советует `down -v` пользователю, правило касается агентов). AC-16: платформенные типы `public` с XML-комментариями (`GenerateDocumentationFile` + `TreatWarningsAsErrors` → CS1591); тексты ошибок пагинации прежние; имена схем `PageResponseOf…` при переносе не меняются (берутся из имени типа без пространства имён); замена `AuditPageResponse` на `PageResponse<AuditEventResponse>` переименует схему в `PageResponseOfAuditEventResponse` (форма JSON та же; избежать можно сопоставлением имён схем или тонким типом — решает plan); `Rejections`, `MaxPageSize`, LIKE схем не касаются; AC-16 — отдельной задачей и коммитом до изменений контракта AC-4/6/7/9, чтобы «`openapi.json` не меняется» проверялся пустым diff.

## Risks
- Перечисление учётных записей по времени ответа «Не помню пароль» (для существующей записи — запись в БД, журнал, SMTP): impact=AC-7 нарушен по смыслу при одинаковом теле ответа, mitigation=принимать запрос и обрабатывать вне запроса; одинаковый немедленный ответ; тихий лимит по e-mail.
- Перечисление приглашённых записей при входе (хэширование пропускается): impact=приглашённые отличимы по времени, mitigation=`SpendHashingTime` для записи без пароля, тест на одинаковый ответ.
- Утечка токена через URL (журналы Ingress/прокси, Referer, история) и его трата почтовыми сканерами: impact=захват учётной записи, mitigation=токен во фрагменте, трата только POST, `replaceState`, по желанию `<meta name="referrer" content="no-referrer">`, хранить только хэш, не логировать тела писем и `ProtocolLogger`, события без токенов и адресов.
- Ссылка остаётся действительной после смены e-mail или блокировки: impact=нарушение AC-5, захват через прежний ящик, mitigation=привязка к stamp + явная очистка при смене e-mail; тесты на каждый случай AC-5 и AC-8.
- Отправка письма в транзакции или под блокировкой дерева: impact=таймаут SMTP (2 мин) останавливает изменения оргструктуры и учётных записей, mitigation=отправка только после фиксации, таймаут из конфигурации ~10–15 с.
- Приглашённый администратор считается «активным»: impact=система без работающего администратора, bootstrap не спасает, mitigation=признак «зарегистрирован» во всех пяти местах, тест гонки по AC-14.
- Гонки принятия приглашения, повторной отправки, блокировки и смены пароля: impact=двойное использование ссылки, принятие после блокировки, mitigation=строка записи под `FOR UPDATE` или маркер конкурентности, детерминированные тесты по AC-14.
- Лимит по адресу за прокси/Ingress (Q8, X-Forwarded-* не разбираются): impact=лимит общий на всех, один злоумышленник выключает «Не помню пароль» и вход, mitigation=известный открытый Q8; лимит по e-mail — по строке записи; разбор заголовков прокси — отдельное решение.
- Лимит по e-mail как способ навредить жертве или исчерпать память: impact=поток писем в чужой ящик, рост разделов в памяти, mitigation=тихий пропуск по времени выдачи в строке записи, для несуществующих адресов ничего не хранить.
- Недоступность SMTP или неизвестные параметры relay (TLS, внутренний CA): impact=письма не уходят, «вечно приглашённые» записи, mitigation=режим TLS и аутентификация из конфигурации (production по умолчанию `StartTls`), понятное сообщение администратору и повторная отправка, `Mail.SendFailed`, доверие внутреннему CA — ручной шаг развёртывания (MS-N), `None` — только для перехватчика.
- Генерация OpenAPI при сборке ломается из-за проверки SMTP/публичного адреса при старте: impact=красная сборка, mitigation=проверять только вне `isToolingRun`.
- Неверный публичный адрес: impact=битые ссылки во всех письмах, mitigation=проверка абсолютного http(s) URL при старте, заметка в README развёртывания.
- Объём переделки тестов (~48 вызовов, перехват писем): impact=долгий impl-test, нестабильные тесты, mitigation=вспомогательный метод с прямой записью хэша, перехват почты только в тестах приглашения и сброса.
- Интерфейс без UX-спецификации до impl (P-2 отложена, `lite`): impact=переделки интерфейса на гейте impl, mitigation=зафиксировать в plan раскладку трёх экранов (переиспользовать карточку входа) и меню строки.
- Ответ 401 от новых анонимных методов: impact=общий обработчик уводит на `/login`, mitigation=400 ProblemDetails с общим текстом для недействительной ссылки.
- Отказ отправки после фиксации (запись есть, письма нет): impact=путаница у администратора, mitigation=явный признак «письмо не отправлено» в ответе (аддитивно), повторная отправка заменяет ссылку.
- Потеря фоновых отправок при перезапуске pod (очередь в памяти): impact=пользователь не получил письмо сброса, mitigation=принять осознанно (повторный запрос; AC-1 разрешает повторную отправку) (решение пользователя 2026-10-08: очередь в памяти, outbox не делается).
