Проверено по дельте (порог — high):
- Имена в `CompetencyResponse` (решение пользователя по combined F1): `CatalogKind.References` + `CatalogEndpoints.NamesAsync` + `CatalogStore.EntryNamesAsync` — один запрос UNION ALL по трём справочникам на страницу или запись, без чтения по строке. Все вызовы `Describe` идут через `NamesAsync` (`CatalogEndpoints.cs:168`, `:213`), поэтому создание, изменение, чтение и список возвращают одинаковые имена. Остальные виды справочников передают `_` и не затронуты. Таблица компетенций берёт имена из строки, `useEntryNames` удалён без оставшихся вызывающих. Проверка видимости имён не делается — это принятое решение (как в `MatrixEntries`).
- Подборщик (`CatalogSelect.tsx:50`): страница растёт на число исключённых записей, но не выше 200 (принятый потолок примерно 180); фильтр перенесён в хук. Отдельная константа на 200 следует уже принятому в коде образцу (`LEVEL_PAGE_SIZE`, `EMPLOYEE_PAGE_SIZE_MAX`).
- Блокировка редактора матрицы на время сохранения (external 1): `ConfigProvider componentDisabled={save.isPending}`. Явные `disabled` в `MatrixBlocks` заменены на `cond || undefined`, нативная кнопка ячейки получает собственный `disabled`. Из памяти проверен факт про приоритет: в `antd/es/button/Button.js:127` стоит `customDisabled ?? disabled`. Блокировка временная (на время запроса), поэтому текст причины не нужен.
- Новый трек (external 2): трек создаётся один раз. После ответа 412 вызывается `readTrack`; `current` для создаваемого трека — это `saved`, поэтому повторное сохранение отправляет перечитанную версию. Для существующего трека поведение прежнее (`!latest`).
- Порядок уровней у опубликованной и архивной версии (external 3): сначала уровни снимка, затем уровни только раннего варианта — принятое решение. Версия в работе следует порядку каталога.
- Тесты: проверки собраны в списки (kind-list, `AssertionScope`); для трека строится отдельное дерево подразделений; фейк создания трека отвечает версией 0. Комментарии в теле функций не добавлены (один удалён). Утверждения в памяти сверены с кодом: `AppDbContextFactory`, `CareerOrg.CreateAsync`, `OrgAsync`.
