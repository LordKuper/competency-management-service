# Sprint 006-promotion-waves

## Goal
Нужно добавить полный процесс повышения сотрудников. От объявления волны повышений до рассмотрения поданных заявок и принятия решений о повышении/увеличении зарплаты/включении в кадровый резерв.

Уточнено на интервью ([research.md](./research.md)): решение одно — «Соответствует критериям для повышения» или «Не соответствует критериям для повышения»; решений о зарплате и кадрового резерва нет. Подход B: итоговые оценки по компетенциям вносит председатель комиссии.

## Acceptance

### Волна повышения
- AC-1: Волну объявляет HR. Он выбирает подразделения волны только из тех, за которые отвечает как ответственный HR, с учётом наследования закрепления (career-framework AC-8). При выборе подразделения по умолчанию отмечаются и все его дочерние подразделения в пределах ответственности HR; с любого дочернего отметку можно снять. В волну входят ровно отмеченные подразделения.
- AC-2: Одновременно может идти несколько волн, но одно подразделение не входит в две незавершённые волны. Попытка создать или изменить волну с пересечением отклоняется с указанием подразделения и волны, с которой оно пересекается.
- AC-3: ~~У волны семь этапов строго по порядку: «Подача заявок» → «Формальная проверка» → «Круговая оценка» → «Сбор артефактов» → «Рассмотрение комиссией» → «Публикация результатов» → «Обратная связь». После последнего этапа волна завершена.~~ Заменён AC-55.
- AC-4: ~~HR задаёт дату начала приёма заявок и дату завершения каждого этапа. При вводе даты начала система подставляет даты завершения всех этапов по длительностям по умолчанию (AC-41); HR может их поменять. Каждая дата завершения не раньше предыдущей.~~ Заменён AC-56.
- AC-5: ~~Даты можно менять и после начала волны, но не дату уже начавшегося этапа на прошедшую и не дату завершившегося этапа. Этап сменяется автоматически, когда наступает дата его завершения; изменения правил волны после старта, кроме дат, недоступны.~~ Заменён AC-57.
- AC-6: При старте волны за каждой парой «подразделение + цель» фиксируется опубликованная версия матрицы, действующая в этот момент (career-framework AC-42…AC-43). Дальше оценка по этой заявке идёт только по ней, даже если позже опубликуется новая версия.
- AC-7: Предстоящие волны и волны на этапе «Подача заявок» видит любой вошедший пользователь, в том числе сотрудники подразделений вне волны: подразделения волны, даты этапов и уровни треков, на которые можно подать заявку. Ведут волну HR, который её объявил, и глобальный администратор. Ответственный HR подразделения волны видит её и заявки своих подразделений.

Ограничений по текущей должности кандидата нет. У сотрудника в одной волне не больше одной незавершённой заявки.~~ Заменён AC-47 (audit, решение пользователя).

- AC-14: ~~Проверка алгоритмическая. С даты приёма или последнего повышения должно пройти не меньше интервала из настройки администратора (AC-41, по умолчанию 12 месяцев). Уровень образования кандидата должен быть не ниже требуемого для цели (AC-15). Стаж не проверяется.~~ Заменён AC-81.

- AC-16: Если интервал не прошёл, HR при вводе даты видит предупреждение и может поставить признак «Игнорировать проверку интервала». Признак и его автор сохраняются.
- AC-17: По окончании этапа система автоматически фиксирует результат проверки каждой заявки. Заявка без даты или с непройденным условием получает терминальный статус «Отклонена по формальным признакам» с перечнем непройденных условий. Остальные идут на круговую оценку.

### Комиссия

### Рассмотрение и решение

Видят также историю рассмотрения прошлых заявок кандидата: волны, цели, итоговые оценки и решения.~~ Заменён AC-67.
- AC-29: Председатель вносит итоговый балл по каждой компетенции. Система считает по ним рейтинг и готовность по правилам версии матрицы (career-framework AC-39…AC-41) и ранжирует кандидатов комиссии в волне по рейтингу.
- AC-30: Рейтинг и ранжирование видят только члены комиссии этого подразделения в этой волне и глобальный администратор. Кандидату они не показываются.
- AC-31: Председатель фиксирует одно решение: «Соответствует критериям для повышения» или «Не соответствует критериям для повышения». Расчёт не выбирает решение автоматически. Решение не меняет оргструктуру.
- AC-32: До окончания этапа председатель может менять итоговые оценки и решение. По окончании этапа заявки без решения фиксируются как «Решение не принято» и попадают в список, который получает ответственный HR (AC-38).

### Поправки audit
- AC-47: Цель заявки — всегда карьерный уровень трека в опубликованной матрице подразделения волны (AC-6); трек матрицы может принадлежать этому подразделению или вышестоящему (career-framework, `POST /matrices`). Должность без трека целью быть не может.
- AC-48: Заявку рассматривает комиссия подразделения волны, которому принадлежит матрица цели (AC-47), по этой матрице; ответственный HR и руководитель — этого подразделения (AC-13, AC-18, AC-25).
- AC-49: Компетенция, по которой все оценивающие отметили «Не наблюдал», при проверке обязательных требований после круговой оценки (AC-21) считается непройденной: её доля в формуле равна 0, а артефакты по ней обязательны (AC-23).
- AC-50: Ожидаемые действия появляются на рабочем столе по правилам стола («один объект — один пункт», [desk](../../../docs/product/requirements/desk.html)): у кандидата — добавить обязательные артефакты, отметить обратную связь; у оценивающего — оценить кандидата; у руководителя — проверить список оценивающих; у ответственного HR — внести даты формальной проверки; у председателя — итоговые оценки и решения.
- AC-51: На рабочем столе у каждого сотрудника есть отдельный блок «Волны повышения»: открытые для подачи заявок волны — с треками целей, сроком приёма и переходом к подаче; предстоящие — с треками целей и датой начала приёма. Если таких волн нет, блок скрыт.
- AC-52: HR и администратор — те же, кто может менять даты волны, — могут откатить незавершённую волну на один из пройденных этапов: выбирают этап и задают новые даты завершения этого и всех следующих этапов; выбранный этап снова становится текущим, дата начала волны не меняется. Завершённую волну откатить нельзя.
- AC-53: При откате сохраняется всё введённое: заявки и самооценка, оценивающие и их оценки, даты формальной проверки и признак игнорирования интервала, артефакты, итоговые баллы и решения председателя, отметки обратной связи. Сбрасывается только то, что противоречит выбранному этапу: при откате на этапы 1–2 — результат формальной проверки (заявка снова «Подана»), при откате на этапы 1–5 — отметка «Решение не принято». Статусы заявок возвращаются к выбранному этапу; принятое решение снова в силе, когда комиссия вновь начнёт рассмотрение. Итоги этапов, которые пройдут заново (итог круговой оценки, обязательные артефакты), пересчитываются при их окончании; письма уходят заново.
- AC-54: Перед откатом система показывает предупреждение со списком всего, что сбросится или пересчитается, с числом затронутых заявок, в том числе что кандидаты перестанут видеть опубликованные результаты до новой публикации. Откат выполняется только после подтверждения.
- AC-55: У волны шесть этапов строго по порядку: «Подача заявок» → «Формальная проверка» → «Круговая оценка» → «Сбор артефактов» → «Рассмотрение комиссией» → «Обратная связь». Окончание этапа — крайний срок, к которому заявки доходят до нужного статуса; действие доступно раньше, как только для него всё готово. Публикация результатов — мгновенное событие в момент окончания этапа «Рассмотрение комиссией», сразу за ним начинается «Обратная связь». После последнего этапа волна завершена.
- AC-56: HR задаёт дату начала приёма заявок и дату завершения каждого этапа. Дата начала не раньше чем через 7 календарных дней после объявления волны; при правке до старта — не раньше даты объявления плюс 7 дней. При вводе даты начала система подставляет даты завершения по длительностям по умолчанию (AC-71) в рабочих днях без суббот и воскресений: каждый этап начинается в рабочий день после завершения предыдущего и заканчивается в рабочий день. HR может их поменять. Каждая дата завершения не раньше предыдущей.
- AC-57: При объявлении волны даты не раньше сегодняшнего дня; при правке волны прошедшие даты допустимы, дату завершения текущего этапа можно менять, в том числе продлевая этап. Нельзя менять дату начала после старта и даты завершившихся этапов. Этап сменяется автоматически, когда наступает дата его завершения; изменения правил волны после старта, кроме дат и отката (AC-52), недоступны.
- AC-58: Кандидат предлагает не меньше 5 оценивающих, с которыми работал последние полгода, из них не меньше 2 из других подразделений, чем подразделение его основного назначения. Оценивающие — работающие сотрудники, кроме самого кандидата. Для оценивающего без учётной записи указывается электронная почта для приглашения в систему; приглашение уходит только на адрес, подтверждённый руководителем подразделения цели или ответственным HR. Без 5 и 2 оценивающих заявка не отправляется.
- AC-59: Пока идёт этап «Подача заявок», кандидат создаёт черновик заявки, правит его и может удалить; предупреждение об образовании (AC-10) он видит до отправки. Отправленную заявку менять нельзя. Отозвать её он может, пока по ней не принято решение: председатель не зафиксировал решение (AC-31) и заявка не отклонена по формальным признакам (AC-17). Взамен отозванной до окончания этапа можно отправить новую. Черновик, не отправленный до окончания этапа, в волне не участвует и виден только кандидату. Отозванная заявка дальше не рассматривается и остаётся в его истории.
- AC-60: Ответственный HR подразделения цели вносит и правит дату приёма на работу или последнего повышения и признак AC-16 с момента отправки заявки до окончания этапа «Формальная проверка». Результат проверки пересчитывается при каждом сохранении и виден HR; окончательно он фиксируется по AC-17.
- AC-61: С момента отправки заявки до окончания этапа «Формальная проверка» руководитель подразделения цели может дополнить или скорректировать список оценивающих кандидата и подтвердить почту оценивающих без учётной записи (AC-58). Правило AC-58 (не меньше 5, не меньше 2 из других подразделений) действует и после правки. По окончании этапа список окончательный.
- AC-62: По окончании этапа «Формальная проверка» система сначала отправляет приглашения зарегистрироваться в системе оценивающим без учётной записи на подтверждённые адреса, затем каждому оценивающему допущенных кандидатов — одно письмо со списком всех людей, которых ему нужно оценить. Оценки ставятся на этапе «Круговая оценка» (AC-19).
- AC-63: Система отправляет письма: сотрудникам подразделений волны — об объявлении волны при объявлении и отдельно о начале приёма заявок; оценивающим — по AC-62 и напоминание перед окончанием этапа «Круговая оценка»; кандидату — о результате формальной проверки и о публикации результатов; ответственному HR — о заявках, ожидающих формальной проверки, и о заявках без решения; членам комиссии — о заявках, поступивших на рассмотрение.
- AC-64: ~~Кандидат добавляет к компетенциям артефакты — текстовое описание и необязательные ссылки на документы во внешних системах, файлы не хранятся: по желанию в черновике заявки и на этапе «Сбор артефактов».~~ Заменён AC-85.
- AC-65: Кандидату, который по AC-21 не проходит обязательные требования, на этапе «Сбор артефактов» артефакты обязательны по каждой компетенции, где средний балл ниже требуемого; рядом с ними кандидат видит пояснение, что без артефакта компетенция, скорее всего, не будет подтверждена. Без них к окончанию этапа заявка поступает к комиссии с отметкой «Обязательные артефакты не предоставлены». Остальным артефакты необязательны.
- AC-66: Председатель обязателен, это любой член комиссии. Без председателя волна с этим подразделением не стартует, а заявки этого подразделения не поступают на рассмотрение.
- AC-67: ~~Заявка поступает на рассмотрение комиссии: кандидата, прошедшего требования по AC-21, — сразу по окончании этапа «Круговая оценка»; остальных — как только поданы все обязательные артефакты, но не позже окончания этапа «Сбор артефактов». Члены комиссии видят карточку поступившей заявки: самооценку, сводку круговой оценки (AC-20), артефакты (добавленные на этапе «Сбор артефактов» — сразу), результат формальной проверки, требования версии матрицы, а также историю рассмотрения прошлых заявок кандидата: волны, цели, итоговые оценки и решения. Председатель вносит итоговые оценки и решение (AC-29, AC-31) с момента поступления заявки.~~ Заменён AC-80.
- AC-68: С публикации результатов кандидат видит по своей заявке: итоговые оценки и их соответствие требованиям матрицы, прохождение формальных признаков и решение.
- AC-69: Обратная связь даётся вне системы. С публикации результатов кандидат отмечает в системе, что получил её. Отметку можно поставить до завершения волны.
- AC-70: При публикации результатов система отправляет письмо всем кандидатам волны, кроме отклонённых по формальным признакам и отозвавших заявку, с просьбой отметить получение обратной связи по факту.
- AC-71: Глобальный администратор задаёт в настройках минимальный интервал между повышениями (по умолчанию 12 месяцев) и длительности этапов волны по умолчанию в рабочих днях; по умолчанию: подача заявок 10, формальная проверка 2, круговая оценка 5, сбор артефактов 2, рассмотрение комиссией 5, обратная связь 5.
- AC-72: На каждом шаге демо-режима все данные экрана заполнены синтетическими значениями, включая даты этапов волны; пустых полей, кроме намеренно пустых по сценарию, нет.
- AC-73: «Оргструктура» и «Карьерная модель» — отдельные пункты основного меню, не в группе «Справочники».
- AC-74: Экраны каждой роли процесса повышения — кандидата, HR, руководителя, оценивающего, члена комиссии, председателя и администратора — переработаны в отдельном раунде дизайна: компактнее, поля и действия в логичном порядке. Макеты утверждает пользователь до реализации.
- AC-75: На каждом экране приложения в панели навигации есть кнопка «Справка» (значок «?»). По нажатию экран затемняется, и система пошагово показывает, что делается на этом экране и зачем.
- AC-76: На экране заявки кандидат видит предварительный рейтинг по своей самооценке: процент готовности, порог, выполнение требований к критическим компетенциям и число неоценённых компетенций (они считаются как 0). Рейтинг рассчитывает сервер тем же алгоритмом, что и для комиссии (порт `ICareerModel`), и обновляет его при изменении самооценки; SPA формулу не дублирует.
- AC-77: На текущем треке кандидата (уровень определяется связью его должности с уровнем трека) целью можно выбрать только следующий уровень; на другом треке — любой уровень. Сервер отклоняет иную цель, SPA предлагает только допустимые уровни.
- AC-78: Уровень образования хранится в карточке сотрудника оргструктуры. Новая заявка подставляет его из карточки; если кандидат меняет его в заявке, при отправке заявки карточка обновляется. Уровни: «Среднее общее образование», «Среднее профессиональное образование», «Высшее образование — бакалавриат», «Высшее образование — специалитет, магистратура», «Высшее образование — подготовка кадров высшей квалификации».
- AC-79: В карьерной модели два типа компетенций: «Критическая» и «Дополнительная». Компетенции типа «Профильная» миграцией переводятся в «Дополнительная», тип по умолчанию — «Дополнительная». Экраны процесса отмечают только критические компетенции.
- AC-80: Заявка поступает на рассмотрение комиссии: кандидата, прошедшего требования по AC-21, — по окончании этапа «Круговая оценка»; остальных — когда кандидат на этапе «Сбор артефактов» нажимает «Отправить на рассмотрение», но не позже окончания этапа. Если приложены не все обязательные артефакты, перед отправкой кандидат видит предупреждение со списком недостающих и может отправить заявку. Не отправленная к концу этапа заявка поступает как есть, при недостающих артефактах — с отметкой AC-65. После отправки артефакты изменить нельзя. Члены комиссии видят карточку поступившей заявки: самооценку, сводку круговой оценки (AC-20), артефакты, результат формальной проверки, требования версии матрицы и сводку прошлых заявок (AC-84). Председатель вносит итоговые оценки и решение (AC-29, AC-31) с момента поступления заявки.
- AC-81: Проверка алгоритмическая. С даты приёма или последнего перехода до даты публикации результатов карьерной сессии (окончание этапа «Рассмотрение комиссией») должно пройти не меньше интервала из настройки администратора (AC-71, по умолчанию 12 месяцев). Уровень образования кандидата должен быть не ниже требуемого для цели (AC-15). Стаж не проверяется.
- AC-82: Глобальный администратор ведёт перечень сотрудников и должностей, которых нельзя указывать оценивающими и приглашать в систему. В поиске оценивающих у кандидата, руководителя и HR они показаны недоступными с пометкой «Указание этого сотрудника запрещено»; сервер отклоняет их добавление. Оценивающий, уже включённый в список до попадания в перечень, остаётся в нём с отметкой.
- AC-83: Тексты интерфейса, писем и рабочего стола: «карьерная сессия» вместо «волна повышения», «Заявка на карьерный переход» вместо «Заявка на повышение», пункт меню «Карьерные переходы» вместо «Повышение», решения «Соответствует критериям для перехода» / «Не соответствует критериям для перехода» (AC-31), «Минимальный интервал между карьерными переходами» (AC-71), «последнего перехода», «Настройки карьерных сессий». Имена в коде и API (`promotion`, `wave`) не меняются.
- AC-84: На форме рассмотрения у члена комиссии и председателя есть сводка прошлых заявок кандидата с принятым решением: карьерная сессия, цель, готовность, выполнение требований к критическим компетенциям, решение; отозванные и не допущенные заявки в неё не входят. По каждой компетенции показано изменение средней круговой оценки по сравнению с последней такой заявкой («без изменений», «новая», если компетенции в ней не было). Сводку и изменения рассчитывает сервер.
- AC-85: Кандидат добавляет к компетенции до 10 артефактов: у каждого описание «Что сделано» и одна обязательная ссылка на документ во внешней системе; файлы не хранятся. Артефакты добавляются по желанию в черновике заявки и на этапе «Сбор артефактов» до отправки на рассмотрение (AC-80). Обязательный артефакт по AC-65 считается приложенным, если к компетенции есть хотя бы один.
- AC-86: На рабочем столе есть действие по каждому подразделению, у комиссии которого нет председателя; его видят ответственный HR подразделения и глобальный администратор (по всем действующим подразделениям). Причина — «Комиссия не сформирована», если комиссию подразделения ещё не сохраняли (председатель и члены не назначены), или «В комиссии нет председателя», если комиссия сохранена, но председатель не назначен или больше не может действовать. Без председателя подразделение нельзя включить в карьерную сессию, а его заявки не поступают на рассмотрение (AC-66). Действие открывает экран «Комиссии» на этом подразделении и пропадает, как только председатель назначен.
- AC-87: Все письма системы — приглашение и сброс пароля, письма справочника и матрицы компетенций, письма карьерных переходов — уходят в формате HTML вместе с текстовой версией для почтовых программ, которые HTML не показывают. Ссылки в HTML-письме кликабельны, текст ссылки называет действие («Задать пароль», «Подать заявку», «Открыть страницу комиссии»). Имена, названия и комментарии из системы показываются в письме как текст и не становятся разметкой.
- AC-88: Пароль может содержать кириллицу: русские заглавные и строчные буквы засчитываются в требования «заглавная буква» и «строчная буква» наравне с латинскими. Русская буква больше не считается специальным символом. Остальные требования к паролю — длина, цифра, специальный символ — не меняются.
- AC-89: В блоке «Что можно сделать» на рабочем столе есть карточка «Объявить карьерную сессию»; её видят глобальный администратор и HR. Карточка показывается, когда в новую карьерную сессию можно включить хотя бы одно подразделение: оно действует и пользователь за него отвечает (HR — за свои подразделения, администратор — за все), у его комиссии есть председатель, и оно не входит в незавершённую карьерную сессию. Карточка открывает экран объявления карьерной сессии.
- AC-90: Если у подразделения не назначен руководитель, его матрицы создаёт и ведёт руководитель ближайшего вышестоящего подразделения, у которого руководитель назначен: подразделение есть в списке «Подразделение» конструктора матрицы, руководитель дорабатывает возвращённые версии, видит действия по этим матрицам на рабочем столе и получает о них письма. Шаг согласования вышестоящим руководителем для матрицы такого подразделения пропускается — версия сразу уходит ответственному HR. Правило действует по оргструктуре на момент действия: как только подразделению назначают руководителя, его матрицы ведёт этот руководитель, а шаг 1 снова согласует вышестоящий. Черновые записи справочников и связывание должностей с треками остаются за руководителем самого подразделения.
- AC-91: Матрица подразделения по треку или по должности действует во всех нижестоящих подразделениях, у которых нет своей опубликованной матрицы по этому треку или этой должности: для сотрудника действует опубликованная матрица его подразделения, а если её нет — матрица ближайшего вышестоящего подразделения по тому же треку или должности. Своя опубликованная матрица нижестоящего подразделения заменяет унаследованную для него и для его нижестоящих без своей; пока своя в черновике или на согласовании, действует унаследованная. Для сотрудников унаследованная матрица действует так же, как своя: видна в «Моё место», по ней идут карьерные сессии, рабочий стол не просит построить матрицу по этому треку. На странице матрицы видно, в каких подразделениях она действует.

## Out of scope (optional)
- Решения о зарплате и кадровый резерв (заменены решением о соответствии критериям).
- Изменение оргструктуры по решению: перевод на должность выполняется отдельно.
- Хранение файлов-артефактов.
- Проверка стажа.
- Независимые предварительные оценки членов комиссии (подход A не выбран).
- Отмена волны и ручное переключение этапов вперёд (откат назад — AC-52…AC-54).
