PRD — Sprint 004 · role-desktop-user-journeys

35 stories · 232 AC · updated 2026-10-12

Проблема

Пользователь работает с набором табличных разделов по сущностям и сам должен понять, что от него ждёт система; нужен рабочий стол, который для каждой роли показывает ожидаемые действия, напоминает о новых, ведёт по шагам через основные сценарии и превращает пробелы целостности карьерной модели и оргструктуры (должность без трека, уровень без должности, брошенные записи) в понятные пункты без дублей.

Пользовательские истории

Любой пользователь 6
  • as пользователь любой роли, I want после входа попадать на рабочий стол — первый пункт меню, so that начинать работу с того, что ждёт от меня система, а не с таблиц сущностей.
  • as пользователь с несколькими ролями, I want один объединённый стол без повторов одного и того же действия, so that не разбираться, по какой роли пришло действие.
  • as пользователь, I want видеть в шапке счётчик ожидаемых действий и получать письмо о новом, so that замечать новое, не открывая стол.
  • as пользователь, I want видеть на столе и в сценариях только то, что мне положено, и чтобы мои данные стола не были доступны другим, so that стол не раскрывал чужое и неопубликованное.
  • as пользователь настольного компьютера или планшета, I want экраны в едином стиле интерфейса, so that новые экраны не отличались от остального приложения.
  • as пользователь, I want, чтобы один объект был на столе одним пунктом, а несколько находок по нему — причинами внутри пункта, самая важная первой, so that стол не повторял одно и то же разными словами и не раздувал счётчик.
Руководитель подразделения 6
  • as руководитель подразделения, I want видеть ожидаемые от меня действия: возвращённую версию, неотправленный черновик, версию подчинённого подразделения на согласовании, подразделение без опубликованной матрицы, so that не пропустить то, что стоит на мне.
  • as руководитель подразделения, I want построить матрицу компетенций пошаговым сценарием, создавая недостающий трек и компетенцию, не уходя из него, so that довести матрицу до отправки на согласование без поиска по разделам.
  • as руководитель подразделения (автор версии), I want доработать возвращённую версию на одном экране с понятными последствиями трёх решений, so that осознанно принять, доработать или откатить правки согласующего.
  • as руководитель подразделения (согласующий шага 1), I want экран рассмотрения версии подчинённого подразделения с разницей и проверкой полноты, so that принять решение без поиска контекста.
  • as руководитель подразделения, I want получить письмо, когда моя версия возвращена или версия пришла мне на согласование, so that узнать об этом без захода в систему.
  • as руководитель подразделения, I want видеть проверки целостности моих должностей, треков и матриц — должность без трека, трек без должностей или уровней, матрица, не покрывающая уровни трека, — so that вовремя исправить пробелы или передать их ответственному HR.
HR 4
  • as HR, I want видеть версии, ждущие моего согласования (шаг 2), черновые записи справочников на утверждение и — справочно — подразделения моей ответственности без опубликованной матрицы, so that различать то, что я должен сделать сам, и то, о чём стоит знать.
  • as HR, I want утверждать черновые записи справочников из одной очереди, не выходя из неё, so that быстро разобрать накопившееся.
  • as HR, I want получать письмо, когда версия пришла на мой шаг согласования или появилась черновая запись справочника на утверждение, so that реагировать вовремя.
  • as HR, I want видеть проверки по подразделениям моей ответственности — связи должностей с треками, подразделения без руководителя, версии, задержавшиеся на шаге 1, неиспользуемые записи каталога, — so that держать карьерную модель в порядке.
Глобальный администратор 6
  • as глобальный администратор, I want видеть черновые записи на утверждение, подразделения без руководителя или без ответственного HR и непринятые приглашения, so that довести оргструктуру и учётные записи до рабочего состояния.
  • as глобальный администратор, I want отправить приглашение повторно прямо со стола и увидеть итог отправки письма, so that не искать учётную запись в списке пользователей.
  • as глобальный администратор, I want подключить подразделение на одном экране — руководитель, HR, должности, учётные записи — с отметкой пробелов, so that закрывать пробелы на месте.
  • as глобальный администратор, I want принять сотрудника одним сценарием: карточка, должность, по желанию учётная запись с приглашением, so that не переключаться между разделами.
  • as глобальный администратор, I want видеть проверки оргструктуры и учётных записей — должность сотрудника вне перечня подразделения, пустой перечень, учётная запись без сотрудника, руководитель или HR без действующей учётной записи, — so that замечать расхождения, не просматривая справочники.
  • as глобальный администратор, I want разобрать находки оргструктуры одной очередью с действием на месте, so that навести порядок без поиска по разделам.
Ведущие карьерную модель (руководитель, HR, администратор) 4
  • as тот, кто вправе править трек, I want связать должности с уровнями трека на одном экране, видя доступные должности с числом сотрудников и уровни без должностей, so that уровень сотрудника определялся по его должности.
  • as владелец карьерной модели, I want, чтобы трек не становился действующим, версия матрицы не отправлялась на согласование и не публиковалась, пока у уровня нет связанной действующей должности, so that в опубликованной модели каждый уровень был достижим по должности.
  • as HR или глобальный администратор, I want привести каталог в порядок очередью неиспользуемых записей — удалить или деактивировать на месте, so that справочники не накапливали брошенное.
  • as HR или глобальный администратор, I want перед подтверждением публикации видеть явный перечень всего, что опубликуется вместе с ней, so that не опубликовать лишнего вслепую и понимать причину отказа.
Сотрудник 3
  • as сотрудник без ролей процесса, I want стол, который честно показывает, что действий для меня нет, и предлагает доступные сценарии, so that знать, что от меня ничего не ждут.
  • as пользователь, привязанный к сотруднику, I want видеть своё место в компании — подразделение, должность, руководителя, ответственного HR и опубликованные матрицы моего подразделения, so that понимать, какие требования ко мне действуют.
  • as сотрудник, I want видеть карьерные треки моей должности, мой текущий уровень и следующие уровни с требованиями — или честное сообщение, что для моей должности трека нет, so that понимать, куда расти.
Потребитель API и команда разработки 6
  • as потребитель API, I want, чтобы существующие методы не ломались, а новые были описаны в документации, so that обновление не нарушило работу клиентов.
  • as владелец проекта, I want правило проверки UI по таблице компонентов DESIGN.md перед коммитом, so that типовые замечания ревью не повторялись.
  • as владелец проекта, I want правило о блокировке правки на время сохранения, переходах при несохранённых правках и обработке 412, so that UI-потоки не теряли и не перезаписывали чужие правки.
  • as владелец проекта, I want видеть макет каждого нового экрана на gate plan, so that замечания по экранам собирались до impl.
  • as владелец проекта, I want, чтобы рецепты scratch-БД и запуска API в памяти агента были отнесены к impl-test, so that impl не запускал лишних проверок.
  • as владелец проекта, I want, чтобы агенты правили файлы своей памяти точечно, so that память не затиралась целиком.
