Сценарии (потоки)

Спринт добавляет слой «рабочий стол»: первый пункт меню, куда ведёт вход, где для каждой роли собраны ожидаемые действия (с счётчиком в шапке и письмами) и карточки сценариев; десять сценариев — пошаговые экраны вместо таблиц по сущностям. Нынешние разделы остаются вторичным доступом. Все экраны построены только на токенах и компонентах DESIGN.md; новых токенов этот спринт не вводит. Экраны сценариев живут под адресом /desk/… (предложение, окончательные адреса фиксирует ADR/plan; они нужны письмам), корень приложения перенаправляет на /desk, а раздел «Рабочий стол» в шапке определяется по началу адреса, как и остальные.

Решения UX, не заданные PRD

PRD фиксирует состав и поведение, но оставляет раскладку экранов UX. Ниже решения, принятые при проектировании; они вынесены для ревью, чтобы их можно было поменять до plan.

№РешениеПочему и что отвергнуто
U-1Меню: «Рабочий стол» (со счётчиком), «Справочники» (список: «Оргструктура», «Карьерная модель»), «Администрирование» (как сейчас, только администратор).Названия берём из формулировки sprint.md; «Администрирование» уже список, вкладывать его в «Справочники» значило бы два уровня вложенности. Цена: разделы «Оргструктура» и «Карьерная модель» теперь на один щелчок дальше.
U-2Счётчик — круглая метка (rounded-full) на пункте «Рабочий стол»: заливка accent, цифры surface-inverse (9.6:1), «99+» при числе больше 99; при 0, во время первой загрузки и при ошибке метки нет. Нового токена нет: пара и форма уже описаны в DESIGN.md («accent … badge fill», rounded-full для count badges).Метка на залитом primary текущем пункте отделяется от фона контрастом около 3.7:1 (расчёт по hex, ±0.05; ≥ 3:1 для не-текстового элемента). Отвергнуто: danger (занимает «критично», а счётчик — не авария).
U-3Строка стола — один объект; причины списком внутри строки (первая — самая важная, по таблице 2 PRD); группа строки определяется её первой видимой причиной, а название группы — действие («Согласовать версии»), без названия роли.AC-2.2/AC-30.8; пользователь с несколькими ролями не должен разбираться, по какой роли пришло действие (US-2), поэтому роль в строке не показывается.
U-4Длинные списки: в каждой группе первые 10 строк, под ними «Показать ещё 20» (подгрузка в ту же таблицу), число в заголовке группы — полное. Короткие списки не показывают никакого управления.Ссылка «в отфильтрованный вторичный раздел» отвергнута: у вторичных разделов нет фильтров по таким находкам, а счётчик равен полному числу пунктов — до каждого пункта нужно добраться. Нумерованные страницы отвергнуты: строки исчезают по мере выполнения, номера страниц «плывут». Для крупных очередей у группы есть ссылка «Открыть очередь».
U-5Справочная группа «К сведению» — внутри блока «Ожидают вашего действия», под действиями; по умолчанию свёрнута, заголовок с полным числом всегда виден, внутри — подгруппы по виду; строки без столбца действий (ссылка на объект).AC-5.4/AC-5.5: не входит в счётчик и не отменяет «Всё сделано». Свёрнуто, чтобы сотни справочных строк HR на корне не заслоняли действия (ux-principles 2, 5). Состояние свёрнутости не запоминается.
U-6«Что можно сделать»: карточка каждого доступного по роли сценария показывается всегда, с подписью «Ждут вас: N» или «Сейчас таких нет»; карточка не бывает недоступной. Сценарий, которому нужен объект (подразделение, трек), открывается с выбором объекта внутри экрана.AC-2.8: недоступные по роли не показываются, а отсутствие объекта — не недоступность по роли. Недоступная карточка требовала бы причины; пустое состояние самого экрана объясняет лучше.
U-7Мастер «Построить матрицу»: шесть шагов в горизонтальном Steps; каждый шаг сохраняет черновик кнопкой «Сохранить и далее»; пока есть несохранённые правки, переходы между шагами и выход заблокированы с видимой причиной (AC-20.2).В DESIGN.md Steps описан вертикальным для стадий волн; горизонтальное исполнение — то же состояние токенов step-*, без нового токена, но Notes компонента стоит дополнить при promote. Вертикальный список слева выглядел бы боковой панелью.
U-8Шаг 1 «Трек и шкала» включает подразделение и шкалу (нужны для создания версии); блок компетенции выбирается на шаге 3, коэффициенты блоков и пороги — на шаге 4.Названия шагов в AC-8.2 не перечисляют подразделение и шкалу, но без них версию не создать (MatrixCreateModal).
U-9Уровни без должности: на шаге 1 (у выбранного трека), в проверке полноты (шаг 5) и на экранах 9 и 10 подсвечены тегом «Нет действующей должности»; рядом либо «Связать должности» (если вправе), либо «Обратитесь к ответственному HR: {имя}». Ссылка уводит из мастера на экран «Связать должности с треком» после сохранения.AC-8.16, AC-9.6, AC-10.9. Встраивать экран связывания в мастер отвергнуто: это отдельный сценарий со своим правом (AC-24.5).
U-10«Доработать возвращённую версию»: три равных карточки решений, главной кнопки на странице нет; каждая карточка со своим подтверждением; «Принять и доработать» ведёт в мастер на шаг 3, «Откатить правки» — на шаг 5.Какое решение «основное», решает автор; выделять одно значило бы подталкивать. «Откатить правки» — красное подтверждение (необратимо). «Принять правки» при публикующем шаге показывает перечень каскада (AC-34.7).
U-11«Согласовать версию»: правки согласующего вносятся на существующей странице матрицы (кнопка «Внести правки»); экран показывает их как «Изменено вами», «Согласовать» недоступно с причиной (AC-10.7); перечень каскада — раздел экрана и повтор в подтверждении публикации.Второй редактор матрицы удвоил бы поддержку. Перечень дважды, потому что AC-34.5 требует его «перед подтверждением», а раздел на экране нужен для оценки до решения.
U-12Очереди (AC-11, AC-32, AC-33): две колонки, слева список с «Показать ещё 20», справа выбранная запись; после решения открывается следующая; кнопка «Утвердить» у черновика трека с отметкой «утверждать рано» недоступна с причиной; подпись кнопки называет последствие («Утвердить вместе с 3 записями»).Правило недоступности с причиной (design-system §7). Сервер всё равно проверяет и отвечает 409 при гонке.
U-13«Подключить подразделение»: пять строк-пробелов с отметкой «Готово» или «Не хватает» и действием в окне; пустой перечень отмечается и у подразделения без сотрудников (AC-12.5), с пояснением, что на столе этого пункта нет.Одно окно на действие, как в нынешней оргструктуре (переиспользуются UnitHrModal, UnitPositionsModal, форма учётной записи).
U-14«Принять сотрудника»: сотрудник создаётся на шаге 1 (кнопкой «Создать сотрудника и продолжить»), а не в конце; итог показывает частичный результат, если шаг 2 не удался.Одну транзакцию через три модуля не собрать (audit, риск порядка блокировок); честный итог лучше скрытого отката.
U-15«Моё место в компании»: следующие уровни свёрнуты в строки с числом требований, требования раскрываются по уровню; уровни без опубликованной матрицы показываются без требований с текстом причины.AC-14.9/14.10. Раскрытие по уровню оставляет экран коротким при длинных треках.
U-16«Связать должности с треком»: слева уровни со связанными должностями, справа таблица доступных должностей с числом сотрудников и кнопкой «Связать с уровнем ▾» (список уровней); «Снять» у последней действующей должности уровня действующего трека недоступно с видимой причиной, отказ 409 — запасной путь.AC-31.3 требует показывать доступные должности на экране, а не за окном; одна видимая кнопка в строке укладывается в «не больше двух действий».
U-17Письма — обычный текст (как существующие письма AccountMail), «Здравствуйте!» без имени, тема оканчивается на «в системе «Калибр»», в тексте нет комментария согласующего и содержимого версии, внизу одна строка «Это автоматическое письмо…».Неопубликованное содержимое не должно уходить по почте (AC-16.5); читатель открывает ссылку и видит его по правам. Строка про автоматическое письмо — необязательна, оставлена на утверждение.
U-18Если повторное приглашение не ушло по почте, пункт со стола всё равно исчезает (ссылка уже новая); окно «Письмо не отправлено» говорит об этом и отправляет повторять из списка «Пользователи».Пункты вычисляются по данным (AC-2.12); альтернатива — держать пункт до принятия приглашения — прямо противоречит AC-6.5 (ссылка действует). Принять сознательно.
U-19Экран входа при возврате на цель показывает информационную подсказку «После входа откроется страница, на которую вела ссылка»; цель, ставшая бессмысленной (версия уже не ждёт решения), открывается с пояснением и ссылкой на стол.Без подсказки вход по ссылке из письма выглядит как потеря цели; AC-15.13 требует только сам возврат.
U-20Объект, который пользователь не вправе читать, открывается как «Страница не найдена» (без утечки существования); известный объект с запрещённым действием — предупреждение «Недостаточно прав для этого действия».AC-16.3 (403/404 по правилам подсистем); соответствует существующему поведению каркаса.
U-21Утверждение записей в существующих разделах (AC-34.6) показывает окно с перечнем публикуемого только когда у публикации есть каскад; без каскада действие выполняется сразу, как сейчас.Минимальное изменение существующих экранов. Альтернатива — окно для каждой записи — добавляла бы клик без пользы в типовом случае.
U-22Адреса экранов сценариев — под /desk/… (/desk/review/{версия}, /desk/rework/{версия}, /desk/drafts, /desk/matrix-builder, /desk/connect-unit, /desk/onboard-employee, /desk/my-place, /desk/track-positions/{трек}, /desk/catalog-cleanup, /desk/org-cleanup); корень / перенаправляет на /desk.Раздел меню определяется по началу адреса, так «Рабочий стол» подсвечивается на всех экранах сценариев. Окончательные адреса — за ADR/plan: письма их используют.
U-23Давность — относительная («3 дня назад») с датой под ней; у приглашения — срок ссылки с тегом «Истекла» или «Скоро истечёт». Столбец «Давность» есть только в группах, где пункты событийные (AC-2.5), в остальных его нет.AC-2.5/2.6: пустой столбец во всех строках вводил бы в заблуждение.

Шапка: «Рабочий стол» первым пунктом, счётчик, группа «Справочники»

Purpose
Сделать рабочий стол первым пунктом меню и показать на нём число ожидаемых действий; нынешние разделы оставить вторичным доступом (AC-1, AC-3).
Entry from
Любой экран при действующей сессии; после входа — рабочий стол.
Exit to

Письма

Темы и тексты — в макете «Письма». Три вида: «Версия матрицы ждёт вашего согласования в системе «Калибр»», «Версия матрицы возвращена вам в системе «Калибр»», «Черновая запись справочника ждёт утверждения в системе «Калибр»». Каждое письмо состоит из строк «Что ждёт вас», «От кого», ссылки отдельной строкой, строки про вход и необязательной финальной строки про автоматическое письмо.

Паттерны взаимодействия

  • Один объект — одна строка стола, одна причина — одна строка внутри. Группа называется действием; роль в строке не пишется; поглощённые и справочные находки при действии не показываются (AC-30).
  • Не больше двух видимых действий в строке (DESIGN.md → Table, Row actions): стол — одно (редко два), очереди и экраны — кнопки в панели записи, а не в строке таблицы. Остальное — в меню «⋮».
  • Очередь (утверждение, каталог, оргструктура): слева список «первые 20 и Показать ещё», справа запись; решение → запись уходит, открывается следующая, фокус переходит на её заголовок; пустая очередь — собственный текст.
  • Мастер: шаги видны всегда, переход вперёд сохраняет шаг; вернуться к пройденному шагу можно, к непройденному — нет; несохранённые правки блокируют переходы с видимой причиной; прервать можно на любом шаге.
  • Решение с последствиями: рядом с кнопкой — что произойдёт; необратимое — красное подтверждение с фокусом на «Отмене»; публикующее — подтверждение с перечнем всего, что опубликуется.
  • Недоступное объясняет себя: недоступная кнопка всегда рядом с видимой причиной («Недоступно: …»), а не с подсказкой.
  • Письмо не решает за систему: пункт стола и письмо независимы; пункт исчезает по данным, письмо уходит по событию (AC-15, AC-2.12).
  • Обновление счётчика: после каждого успешного действия и при переходе/возврате фокуса, без опроса по таймеру (AC-3.4…3.6).
  • Адаптивность. Десктоп — две колонки очередей и связей, таблицы групп; планшет (меньше 992 пикселей) — одна колонка, контролы control-height-lg, поля page-gutter-narrow, таблицы прокручиваются горизонтально (первый столбец закреплён там, где он нужен); сценарий не теряет функций (DESIGN.md → Layout). Мобильный — только адаптивный.
  • Доступность. Контраст и цветовые пары обеспечены токенами DESIGN.md; этот документ правил доступности не вводит. Состояние никогда не передаётся одним цветом: у каждой метки, значка и подсветки есть слово или цифра.
