Wrapped Codex CLI via `codex exec --sandbox read-only -` (full tail per the agent file's `wraps_invoke_args`):

- **Transport**: only the rendered prompt (template + project context + the manifest path) goes through heredoc/here-string stdin. `external.scope.json` and its diff file already exist in the review output dir (written by the orchestrator's `emit-manifest`); the wrapped CLI reads the manifest, `files[]` and the `diff` file by path with its own read-only tools. Never inline the manifest or diff in stdin, never pipe a live `git diff`, never pre-write anything to scratch (size-check with `wc -c` on a pipe). See [[scope-manifest-transport]].
- The captured output ECHOES the prompt first (banner, `user` block, session log), then a `codex` marker line with the final message, then `tokens used`, then the final message REPEATED. Parse the tail (last occurrence), not the head.
- Appending `| tail -c N` to the codex command does NOT shrink what the Bash tool captures: the echo/session log goes to stderr, which the tool merges regardless. When the result is persisted to a tool-results file, `tail -c 6000` that file in a second call to reach the verdict. That buffer is the Bash tool's own, not a file this agent writes.
- Session log may show scary non-fatal ERROR lines: plugin/skill loading failures inside the sandbox, `failed to record rollout items` after the final message, an `rg ... (os error 123)` from a malformed glob, or `EPERM ... mkdtemp` when codex tries `node tests/run.js` (the read-only sandbox blocks temp dirs). Not findings; cross-check against the latest impl-test decisions-log entry.
- `--sandbox read-only` is honored (banner shows it). Typical run is tens to ~150k tokens, within the 10 minute timeout.
- Prompt tail that yields clean output: "Use severity terms: blocker | critical | major | minor | info. Give each finding an id (F1, F2, ...). Cite file:line. You may read repo files for cross-reference (read-only sandbox). Output only the verdict block as your final message." A trailing `dropped_below_floor: <n>` line gives the dropped count; trailing `P<n>: resolved|carry-over|partial - <one sentence>` lines per prior finding give the stalemate input. In framework mode state what counts as code (rules/agents/workflows/manifest) and that cross-file contradictions, dangling refs and unsatisfiable obligations are defects: codex then cross-reads unchanged files.
- Iter 2+: paste the prior finding set inline with "verify fresh, do NOT assume fixed": codex re-checks unchanged files and catches carry-overs. Cross-check decisions-log "resolved" claims and the dispatcher's own resolution summary against the actual diff hunks per file (one Grep per file); both can overstate. When the dispatcher pre-announces an accepted resolution shape, say "do NOT re-flag the shape itself": codex then verifies consistency instead of re-raising.
- Seeded "check whether X" questions get checked, but codex tends to rate a seeded confirmation one tier too high. Calibrate against how internal reviewers rated the PARENT defect in the prior iteration; if the calibrated tier falls below the floor, surface it in a below-floor note so the orchestrator can overrule.
- Codex re-litigates deliberately scoped design choices. Before keeping, read the cited spot plus the plan/decisions-log for a recorded rationale; documented and nothing dangling means drop as nitpick and note it. A rationale living only in the mirror file (not in the SSoT rule it contradicts) does not count.
- Codex line citations are usually exact but can be off by a few lines: verify with Grep/Read and cite the verified line.
- Grep tool: a brace glob in `path` or in the `glob` parameter (`{a/*.md,b/x.html}`) silently returns no matches. Use one Grep call per file with `path` = the file. A single negated glob such as `!**/sprints/**` with `path` = `.asd` works for repo-wide sweeps.
- Self-hosting impl-review scope is the `self_hosting: enabled` row of `external-review.md` Phase-scoped payload, not the consumer row.
- Prior finding set arrives inline in the dispatch payload; never read other iterations' review files.
- Stalemate = identical issue set (same files, lines, messages). A partial fix that moves the defect to a new clause or lands in only some target files is a carry-over: report it as kept (or below-floor-noted) and say which part remains. Consecutive APPROVEs with prior below-floor notes verified resolved is convergence, not stalemate.
- Verifying a "reach carve-out" fix: check the reach statement sits on the SAME line as the SSoT citation in every mirror file, not just somewhere in the section.

## Foreground, explicit timeout, stdout capture only

Run the invocation as a normal foreground Bash call (never `run_in_background`) with `timeout: 600000` on the very first call (canon minimum is 10 minutes; the tool's ~120s default auto-backgrounds long runs). Capture stdout/stderr directly as the review text (`2>&1`). Never redirect codex's own output to a file (`>`, `>>`, `-o`), not even a scratch file deleted afterwards, and never as a workaround for an anticipated timeout, backgrounding or interruption: the contract is "no file writes at all", which covers the CLI's stdout as well as the prompt going in. On an interrupted turn, re-run clean. If a call is auto-backgrounded anyway, read the result from the harness's own reported background-task output; that is tool tracking, not a file this agent chose to create.
