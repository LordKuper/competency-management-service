Task 18 (2026-10-07), EF Core 10.0.12 / Npgsql 10.0.3 / antd 6.6.5 / PostgreSQL 18.6, scratch DB + Release API + Vite preview, all removed:

- **Module direction**: the employee endpoints stay in OrgStructure; the account part is `IEmployeeAccounts.BlockAsync(employeeId, unbind)` (public interface in OrgStructure, `EmployeeAccounts` in UserManagement, scoped, same `AppDbContext`). `EmployeeImpact.OfAsync` computes (units tracked + account via the keyless `EmployeeAccount`, now with `is_blocked`) and is both previewed (`ToResponse`) and applied (`ApplyAsync`), so warning and action share one value. Account side sets `IsBlocked` and `SecurityStamp = Guid` directly (`AppUser.EndSessions`): `UserManager.UpdateSecurityStampAsync` saves at once through `AppUserStore` and swallows the concurrency exception into a result, which would break "one SaveChanges, 412 rolls everything back". An already blocked account gets no stamp change and no audit row; delete only adds `employeeId` to the audit diff.
- **EF**: nulling `OrgUnit.HeadEmployeeId` and `AppUser.EmployeeId` on tracked entities, then `ifMatch.ApplyTo` + `context.Remove(employee)`, then one `SaveChangesAsync` orders UPDATEs before the DELETE by itself (RESTRICT FKs, no 23001); `Employee.Deleted` audit carries every allow-listed old value, no new value. Setting the original `Version` before `Remove` makes the DELETE `WHERE version = @p` (stale -> 412).
- **Forced failure check without a scratch build**: another psql session `begin; update users set version = version + 1 where email = '...'; select pg_sleep(4); commit;`, then dismiss within 1.5 s: the cascade's `UPDATE users ... WHERE version = old` waits, then 0 rows -> 412 after ~2 s with employee active, unit head intact, account unchanged and 0 new audit rows. Race of dismissal vs unit edit, 24 rounds with two curls in the background: always 200/200 or 200/400 (head no longer works), no 500, no deadlock log line. Parallel `( curl ... >> shared-file ) &` lost most result lines; write one file per request.
- **Rules as built**: dismiss of a dismissed employee and rehire of a working one -> 409 (Russian detail); rehire into an inactive unit -> 409; PUT/POST ignore a sent `isActive`; binding an account to a dismissed employee stays a 400 `errors.employeeId` "Сотрудник не работает."; user-role accounts may be unbound (CHECK now `GlobalAdmin AND employee_id IS NULL OR User`), unbound accounts log in and unblock normally. Migration Down fails loudly with 23514 (`ATRewriteTable`) while an unbound user exists, history stays on the new migration; Up/Down/Up clean after removing them.
- **antd cost per card** (prod build via `vite preview`, 2000 employees in one unit, CDP `Performance.getMetrics` ScriptDuration, re-expand): no menu 35 ms, plain `<button>` + `MoreOutlined` 100 ms, `Dropdown` + plain button 540 ms, `Dropdown` + antd `Button` 850 ms. Fix: plain button until first click, then `Dropdown open` around the same button markup (state `boolean | null`, null = never used); CSS class `.org-employee__menu` copies antd's text button from `--ant-*` vars.
- `modal.confirm` DOM: `.ant-modal-confirm`, `-title`, `-content`, `-btns button`; a failed `onOk` followed by `modal.error` gives two `.ant-modal-confirm` nodes; `message.loading(text, 0)` returns the hide function. `Employee.version` is `?: null | number` in the generated type, so card actions need a `version == null` guard even though only administrators reach them.
- A stray `cat > /dev/null; node -e ...` (leftover from a heredoc edit) blocked the shell on stdin for 120 s and moved the call to the background; the `node -e` after it still ran once the `cat` was killed by PID. A `node -e '...'` containing an apostrophe in a C# doc string breaks the shell quoting: write the edit script as a `.cjs` file with the write tool.
