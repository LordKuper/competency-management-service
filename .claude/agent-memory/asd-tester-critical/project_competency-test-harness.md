Backend integration tests run the real API (`dotnet Competency.Api.dll` from the test bin directory, configuration through environment variables) as a child process against one shared Testcontainers PostgreSQL; every host gets its own database. A child process beat an in-process host because per-host settings (rate limit, bootstrap administrator) stay independent and middleware, migrations and locks are the deployed ones. `Program` is internal and `InternalsVisibleTo` exists, but tests prefer HTTP plus raw Npgsql.

- xunit v3 parallelism is per collection (one class); theory rows of a method run serially; a class fixture may take the assembly fixture in its constructor. A test project with zero tests fails (`dotnet test` exit 8, vitest exit 1), so a green baseline needs tests, not configuration.
- Tests sharing a database must not rely on global state. Lists page by name (200 at most), so look an entity up by a unique-name filter, never by position. Anything about the set of administrators needs a dedicated host and a helper that checks the role at sign-in, because a demoted administrator can still sign in. `CareerHost.OrgAsync()` is ONE tree per class: a test that creates tracks or other unit rows there changes what a sibling test counting by unit sees, and that shows only in a whole-class run (every `--filter-method` run stays green); such a test builds its own tree with `CareerOrg.CreateAsync(fixture.Host)`.
- Race tests, two kinds. A gate start (both requests behind a `TaskCompletionSource` created with `RunContinuationsAsynchronously`, every version fetched before the gate, a few rounds with fresh data, outcome set {200, 409} exactly, as in `OrgTreeTests`) is only for a race that does not guard a multi-row invariant; its window is narrow, so it gives no fail-first proof. A race over a multi-row invariant (last administrator, one account per employee, wrong-password counter, dismissal cascade) is built on a held lock or trigger pause, per the recipes below: the test fixes the arrival order, waits through `pg_stat_activity`, and every request, the loser included, has one known status (the last-administrator loser is 409, never 401). Where the order is fixed, do not accept an either-or status such as {200, 401} for the loser; it hides a path that never waited.
- A host that unexpectedly starts inside a "must fail to start" test has to be disposed: a leaked child keeps the runner's stdout pipe open and hangs `dotnet test` (and a `spawnSync` around it) until it is killed by its port.
- Mutation proofs for production code run in a `git archive HEAD` copy outside the repository, never in the working tree; a `node_modules` junction in that copy is removed with `rmdir` before `rm -rf`. A fixture that sorts identically under the wrong algorithm survives its mutation: a green mutation is a finding about the test.
- Host logs: the console logger writes asynchronously, so a record can reach `host.Logs` after the response that caused it; a test that reads it right away flakes (seen once in five runs). Read through `ApiHost.LogsAfterAsync(fragment)` and find records by structured fields (`State.Status`, `State.StackTrace`), not by message text, so a reword stays green.
- A real 5xx without a test hook: on a dedicated host add a CHECK constraint whose name is a unique marker (raw SQL), then send the value it forbids. The error is an unmapped check violation, and Npgsql redacts the row detail, so the constraint name is the one string of the exception message that can prove a log record never carries it.
- A guard that a role cannot bypass (triggers enabled always) is tested inside a transaction: `SET LOCAL session_replication_role = replica`, run the statement, expect the rejection; disposing the transaction rolls back, so a regression cannot damage the shared host's journal.
- A deterministic race needs a pause point inside the first request's transaction, after its reads: on its own host add `BEFORE UPDATE ON employees` calling `pg_advisory_lock(k)` then `pg_advisory_unlock(k)`, hold `k` on an unpooled `NpgsqlConnection`, start the dismissal, wait until `pg_locks` shows it ungranted, fire the second request, wait for `late.IsCompleted || another ungranted lock`, then release. Count waiters through `pg_locks JOIN pg_stat_activity ON pid WHERE datname = current_database()`: `pg_locks` is cluster-wide and parallel classes share the container. A gate-start `TaskCompletionSource` race with a narrow window (an update-binding request is milliseconds) cannot give a fail-first proof; a held transaction can.
- Real fail-first for a review fix: `git archive <prior HEAD sha> src` plus the current `tests/` in a scratch copy, run the whole suite, list the reds. It showed the reviewer's "update-binding races dismissal" path was not reachable before the fix (both take the admin row lock, and one active administrator always exists); that row stays green pre-fix and is proven only by removing every lock from the endpoint. State that in the plan rather than claiming a regression proof. `using var scope = new AssertionScope()` (AwesomeAssertions.Execution) makes a test body report every assertion, so a later one (the response to a change, after the list and the read) gets its own mutation proof instead of hiding behind the first red.
- A race on one account's rows without a trigger: hold `SELECT id FROM users WHERE id = X FOR UPDATE` in a transaction on an unpooled `NpgsqlConnection`, fire N requests, `Waiting.UntilAsync` until `pg_stat_activity` shows N backends with `wait_event_type = 'Lock'` in `current_database()`, then commit. It also works against the pre-fix code (its UPDATEs queue on the same row), so the test reddens on assertions, not on the 30 s timeout. Use a class-fixture host (`HostFixture`) so no other test waits on locks in that database. `ProblemDetails` bodies carry a per-request `traceId`: compare bodies without it. Identity resets `AccessFailedCount` to 0 when it starts a lockout, so assert the lock by a refused right password, not by the count. An unsavable `IdentityResult.Failed` is reachable with `UPDATE users SET user_name = ''` (the user validator rejects it; sign-in still finds the account by e-mail).
- The `AdministratorsHost` class fixture is shared state: a test that fails after blocking the sole administrator makes every later test of the class red ("active ... is empty"). Read the first red only.
- `ApiResponse` once printed its computed `Id` in assertion failures, which turned any failed assertion over responses into a `NullReferenceException` (it hid the deadlock 500 of a lock-order mutation); `PrintMembers` now prints status and body only.
- Python or heredoc edits of the production `.cs` files in a `git archive` copy: the index is LF but `core.autocrlf=true` makes the archive CRLF, so multi-line anchors need `\r\n`, and a bash heredoc (or `sed`) turns `\r\n` inside a Python string into real line breaks; build the separators with `chr(13) + chr(10)` in a script written with the Write tool.
- `dotnet test --tl:off` hands `--tl:off` to the test runner (zero tests, exit 5); `--tl:off` belongs to `dotnet build` only. The scratchpad is shared with the main session: name scratch copies with an entry prefix (`t5-mut`) so a cleanup never removes the caller's files.
- Audit rows of one account are read through `GET /api/v1/audit?action=<Action>&entityId=<id>`; a test that needs "exactly one" reads it after every step of the scenario, so a stray extra write at any step fails it.
- Mutation copies: run `dotnet test --project tests/Competency.Tests/Competency.Tests.csproj` there, not the `.slnx` (it pulls the web project and `node_modules`). Mutating a migration away means deleting its `.cs` and `.Designer.cs`; the model snapshot stays consistent, so the host still starts.
- Web tests: jsdom has no `ResizeObserver` (stubbed in `web/src/test/setup.ts`); Testing Library's accessible name collapses a non-breaking space, so assert the `aria-label` attribute for it; `Intl.Collator("ru")` sorts ё as е, so an ordering fixture must tell ICU order, code-point order and "ё right after е" apart.
- Web screens are tested against a fake network, `web/src/test/fakeApi.ts`, installed by `setup.ts` before the typed client loads (openapi-fetch takes `fetch` once, at `createClient`, and calls it with one `Request`): `fakeApi.on("METHOD /path", handler)`, `fakeApi.calls(route)`, `deferred()` to hold an answer. A request without a handler answers 599. Vitest filters are relative to `web/`; a `web/src/...` filter finds no tests and exits 1 with zero tests, so treat `total === 0` as an error in a mutation runner. `git apply -R` of a fix commit's diff works as a pre-fix copy unless a later commit touched the adjacent lines.
- Waiting traps in those tests: a form that remounts leaves the old input detached, so re-query the field on every step and flush a refetch with one more `user.type` (checking the draft right after `invalidateQueries` passes vacuously on the pre-fix code); an "is not requested" assertion on a debounced query is vacuous until the debounce has run, so use `vi.useFakeTimers()` after render, `fireEvent.change` and `act(() => vi.advanceTimersByTimeAsync(SEARCH_DEBOUNCE_MS))` (a survivor, S8, found this); the focus-return refetch is async, so sync on a positive control (`/auth/me` refetches on focus) before asserting the other routes were not reread. Raising RTL `asyncUtilTimeout` turns a failing `waitFor` into the 5 s test timeout and hides the assertion message; leave the default.
- antd in jsdom: a Dropdown menu item's accessible name includes its icon label ("logout Выйти"), so match `{ name: /Выйти/ }`; a loading Button also carries the icon label, so `getByRole("button", { name: "Сохранить" })` failing means the button is stuck loading; antd Modal prints the harmless "getComputedStyle with pseudo-elements" notice. A search fixture letter can occur in a unit name ("я" is in "Компания"): pick one the fixture lacks. antd `ConfigProvider componentDisabled` locks antd controls, but an explicit `disabled={false}` beats it (pass `cond || undefined`) and a native `<button>` ignores it: a lock test collects the KIND of every control left enabled into one list, not a count. A form that is recreated on success (a `key` bump) makes a "lock stays after success" mutation equivalent, "stays after an error" is not.
- `AppShell` returns null on a 401, but the unauthorized handler navigates first, so replacing that branch is unobservable in jsdom (recorded as a ceiling, not pinned).
- Mail: every host sends to one shared Mailpit container (`MailCatcher`, Testcontainers core generic container, no new package); `TestEnvironment.WithMail` merges its `Smtp__*` into each host's settings. It needs `MP_SMTP_DISABLE_RDNS=true`: without it each SMTP session waits ~10 s for the greeting under Docker Desktop (the suite took 11 min and `Waiting` timed out; the dev compose Mailpit has the same delay), plus `MP_MAX_MESSAGES=0`. Find mail by a unique recipient, never by position. The anonymous forgot-password queue is FIFO and single-reader, so the mail of a sentinel account sent last proves every earlier request was handled before asserting "no mail". The host's JSON log escapes non-ASCII: search `text.JsonEscaped()` as well as the raw text. A closed port (`ApiHost.FreePort()`) is SMTP failure, a started and never accepting `TcpListener` is a mail server that does not answer, a Mailpit started with `MP_SMTP_AUTH_FILE` (`WithResourceMapping` bytes, `user:pass\n`) is the authenticated branch.
- `Scenarios.CreateUserAsync` now creates through the API and writes the password hash directly (link columns cleared, `PasswordHasher<object>`, hash computed once); `InviteUserAsync` is the real passwordless create. `ApiClient.Host` gives extensions the database.
- Link races: `RowLock.HoldAsync` on the account row, start one request, `RowLock.UntilWaitingAsync(host, n)`, start the next, release: Postgres serves row-lock waiters in arrival order, so each order has a fixed outcome (accept-first against block gives 412 for the block, which read the version before the wait). Reset against own-password change with change first is a true race (change saves outside the lock): assert exactly one winner, not which. Use a class-fixture host so the waiter count is the test's own.
- Equivalent mutants: `ClearLink` in change-password is redundant with the stamp binding of the link (remove both to see the test go red); `IsActiveAdministrator`'s `!IsInvited` only matters in a state with no active administrator.
- While the user's Visual Studio runs `Competency.Api.exe` the Debug output is locked and `dotnet test --solution Competency.slnx` fails to copy DLLs: run `-c Release`. Never kill by a command-line pattern that matches your own shell wrappers; kill by PID (a pattern kill took the background wrappers with it). A scratch copy of the tree with a `node_modules` junction: `rmdir` the junction before deleting. A Python patch script via a bash heredoc turns `\n` in its strings into real newlines: write it with the Write tool.
- Startup-validation tests: rows of `PlatformTests.Ac1_StartWithAMissingOrInvalidMailOrLinkSetting_…` are one `InlineData` each (a refused start is ~2 s); a setting is checked by value, so a boundary needs a row on each side (`…294` accepted with a real send, `…295` refused). The shipped `appsettings.json` sits in the test bin, so a shipped default is read in-process with `new ConfigurationBuilder().AddJsonFile("appsettings.json")…Get<SmtpOptions>()`. A BCL limit is confirmed with `dotnet run file.cs` in the scratchpad (.NET 10). A test that uses a property the pre-fix `src` lacks does not compile in the pre-fix copy: delete that test from the copy and prove it by mutation on the current `src`.
- `dotnet test --project … --filter-method` takes a wildcard pattern: a bare method name runs zero tests (exit 8), use `*Name*`. A `sed -i` mutation in a scratch copy rewrites line endings, so show the diff with `diff --strip-trailing-cr`.
- `docs/architecture/tech-reference/` gates test libraries too: Playwright and `Microsoft.AspNetCore.Mvc.Testing` have no reference, so the Tester may not implement with them until the Architect adds one. Check the directory before planning e2e.
- Last-administrator race (`LastAdministratorTests`): `RowLock.HoldActiveAdministratorsAsync` runs the SQL of `ActiveAdministrators.LockAsync`, so the test also holds the victims' rows. Block and dismissal each take the tree advisory lock (`OrgTree`) and then the administrators lock, and either one serializes them alone: dropping just one is an equivalent mutant (green), only dropping both, or `password_hash != null` in `HasOtherAsync`, reddens (the loser answers 200, not 409). The loser must answer 409, never 401: its session was valid when it queued. Wait with `Task.WhenAny(waiting, request)` and assert `request.IsCompleted` is false, so a path that does not wait fails on an assertion, not on the 30 s timeout; run each theory row alone in a mutation, because the first red leaves the shared `AdministratorsHost` without an administrator.
- Held-lock tests (`RowLock.HoldAdvisoryAsync` plus `StartWaitingAsync`) redden at once when a lock is removed, with "The request did not wait for the lock, it was answered: …", under a second a row, so a lock mutation over the whole class costs about a minute. An operation that also touches the held row (a DELETE of the matrix row, an INSERT of a child under its foreign key) waits on that row anyway: dropping `FOR UPDATE` leaves those rows green (equivalent mutants) and reddens only an operation that merely updates a child row.
- Backend mutation runner for production code: extract `git archive HEAD src tests openapi Directory.Build.props global.json .config` into a fresh scratchpad directory; one Node script applies `[id, file, from, to, class names]`, runs `dotnet test --project tests/Competency.Tests/Competency.Tests.csproj --filter-class '*A*' --filter-class '*B*'` (repeated `--filter-class` ORs) and restores the file in `finally`; the output is Russian (`сбой <Name>`, `итог`/`сбой`/`успешно`). Start exactly one runner with the tool's background flag: a second runner on the same copy fails builds with "being used by another process" and garbles the results file; a runner killed with `Stop-Process` skips its `finally`, so re-extract; a directory a build-server process still holds cannot be deleted, so take a new name. `TreatWarningsAsErrors` makes an unread primary-constructor parameter (CS9113) a build failure, so a mutation keeps every parameter read. A bash heredoc turns `\n` inside a JS string into a real newline: anchor on one line.
- To see why a request answered 500, add a throwaway test that throws `host.Logs`: the lines are JSON, read `State.ExceptionType`, `State.SqlState` and the application frames of `State.StackTrace`. Delete the file at once.
- `defect-stalemate` compares the failure line verbatim, so an assertion message that embeds a response body (`traceId`) or random fixture names never repeats and the comparison is blind for those symptoms.
- A test that expects an order decided by a random fixture name (a `Scenarios.Unique` unit name as the last tie-break) fails about half the runs: assert tied rows as a set.
- dnd-kit keyboard sorting runs in jsdom once `Element.prototype.getBoundingClientRect` gives each keyed row a top by its index (`web/src/test/stubRowLayout.ts`, restored in `afterEach`); Space, ArrowUp/Down and Space/Escape then work and the live-region text can be asserted.
- A control whose component type depends on `/auth/me` or `/career/me` (administrator tree select versus a plain select) must not be used before those queries are cached: wait for `queryClient.getQueryData(key)`, then `await act(async () => undefined)`; an early click lands on the placeholder control.
- Dropdowns of closed antd selects stay in the DOM hidden: read the options of one select through `document.getElementById(combobox.getAttribute("aria-controls"))?.closest(".ant-select-dropdown")`.
- Vitest refuses imports outside the web root (`?raw` is denied) and `import.meta.url` is an http URL under jsdom: read the OpenAPI document with `node:fs` from `process.cwd()/../openapi/openapi.json`, with `/// <reference types="node" />` first in the file because `tsconfig` limits `types`. Derive a closed list from a union with `Object.keys({…} satisfies Record<Union, true>)` so a new member fails the typecheck.
- Column-filter wiring across tables: click the header's `.ant-table-filter-trigger`, pick the `menuitem`, press `OK` (tree filter: combobox "Подразделение" and `.ant-select-tree-title`), assert the query string of the last request; scope a nested table with `.ant-table-expanded-row`. Run `biome check --write` on new test files; a Python `open(path, "w")` edit on Windows writes CRLF, which biome refuses, so open with `newline=""`.
- A run of the entry's new tests on a `git archive <prior HEAD> src` copy (repeat `--filter-method`, it ORs; copy the worktree tests in with `tar --exclude=bin --exclude=obj`) sorts them: red ones are fail-first, a green one only guards over-reach and the plan must say so. Suite timing ids continue the sprint's numbering (`suite impl-test#n`): read the ledger's last one before opening.
- Journal and version stamping: the journal interceptor writes one `<Entity>.Updated` row per modified entity whose allow-listed property changed, per `SaveChanges`, and `EntityStampingInterceptor` bumps every Modified versioned entity once per save; `Version` itself is not audited. A save split into several shows as extra journal rows (count assertion); `Entry(e).Property("Version").IsModified = true` bumps a version with no journal row, which proves a version assertion the count assertion would otherwise pre-empt. Rows of a rolled-back request leave nothing in `GET /audit?requestId=`. A created entry comes back as version 0 (the stamper bumps only Modified entities), so a web fake of a create answers 0; a fake answering 1 hid a `saved.version > base.version` condition for a whole review round.
- Schema-derived width sweep: `pg_constraint` (contype 'c', one `conkey`) joined to `pg_attribute` (varchar width is `atttypmod - 4`) with `regexp_matches(pg_get_constraintdef(oid), '''([^'']*)''', 'g')` gives the longest literal a CHECK admits per column, so enumeration members are never listed by hand. Add a `ContainAll` of known columns so a broken join cannot pass vacuously. Mutating the width comparison is equivalent at a clean HEAD; only a pre-fix copy proves the offender branch.
- Probe the pre-fix copy before building a cross-module theory. A write repeated with the tag it already used answers 412 on every plain EF path even when nothing changes (`IfMatch.ApplyTo` set the original `Version`, so the entity counts as modified and the UPDATE matches no row): seven kinds plus ten probe rows were all green pre-fix and the theory was dropped. Only a handler that skips `SaveChanges` for an unchanged document (matrix content) was red. A probe row whose first write is itself a no-op never bumped the version, so its repeat is not stale.
- Delete versus transition race: hold the matrix row (`RowLock.HoldMatrixAsync`), start the matrix delete (it takes the catalogue lock, then waits on the row) with `StartWaitingAsync(…, 1, …)`, then the transition (it waits on the catalogue lock) with `…, 2, …`, release: the delete commits first and the transition finds its version gone. Pre-fix answer 500 (`FirstAsync`), fixed answer 404. Pass the version's tag to both requests (`etag:` on `TransitAsync`) so no extra request runs inside the wait.
- Read-access rewrites need a test per path: single-version reads (`GET matrix-versions/{id}`) and the matrix lists (`GET matrices`, `GET matrices/{id}`, `…/versions`) use different code. A list test over two units of one page (the head of the root unit is the superior approver of the department's matrix but not of the team's) kills a per-unit cache keyed wrongly; a participant who acted and then lost the role kills a dropped acted-on lookup; a blocked nearer head makes the farther head the superior approver for draft-entry visibility. Unfiltered `GET matrices?pageSize=200` is safe on a class host (fewer than 200 matrices).
- A python or JS patch script written through a bash heredoc loses backslashes silently (a `replace` anchor stopped matching and nothing failed): write scripts with the Write tool, build line-ending separators with `String.fromCharCode(13)` and `grep -c` the result.
- Line endings: count CRLF pairs with python on the bytes (`count` of carriage return plus line feed); `grep -c` with a CR pattern reports 0 for a fully CRLF file in this shell. Worktree test files are a mix (some CRLF, most LF); the Edit tool and `open(..., newline='')` keep each file's own.
- Web pre-fix proof: `git archive <commit before the first fix> web` into a scratch directory, a junction for `node_modules` (`cmd //c "mklink /J node_modules <absolute path>"`), copy only the changed test files over it, `npx vitest run <files> --reporter=verbose`. Vitest does not typecheck, so new tests run against old code and fail on assertions. A wholesale-copied test file also brings the older tests of that file that the fix commit adapted: they go red too, so separate them by name before counting. Web mutation runner: one Node script, a single-anchor check per mutation, `vitest run <files> --reporter=json --outputFile=...`, read `assertionResults` with status failed, restore the file in `finally`; multi-line anchors are fine in a `git archive` web copy (LF). The runner starts `node node_modules/vitest/vitest.mjs run …` with an argument array, never `npx` with `shell: true`: the shell splits a `-t` pattern with spaces or `|` into file filters, the wrong tests run and the failures still look plausible.
- `dotnet test --filter-class` and `--filter-method` together are ANDed: a class filter plus a method filter of another class runs zero tests (exit 8). Run the two kinds in separate invocations. The Windows console codepage breaks Cyrillic runner output piped through Python (`UnicodeEncodeError`): write the extracted summary to a UTF-8 file and read it with the Read tool.
- Web test traps met with server-search pickers and paged tables: antd `Select` options are virtualised, so never count them, assert the request (`q`, `page`, `pageSize`) instead; the selected text also sits in the hidden dropdown, so scope it with `within(combobox.closest(".ant-select"))`; `getAllByRole` throws when nothing matches, use `queryAllByRole` for "no actions"; `findByRole("dialog", { name })` found nothing for `AppModal`, locate it by the `.ant-modal-title` text and `closest('[role="dialog"]')`; a pagination item is `getByTitle("2")` and its size changer `.ant-pagination-options .ant-select`; `toBeVisible()` fails inside modal bodies in jsdom, use `toBeInTheDocument()`; `Form.useWatch` is `undefined` on the first render, so a guard that clears a value must wait for the data of the watched unit (removing it reddens the control test). A mutation that keeps every excluded option can fail on the free option missing from the window of about eight rendered rows before it reaches the "excluded are absent" assert; keep one excluded option (`exclude.slice(1)`) to reach it.
- Removing `crypto.randomUUID` for a plain-HTTP test: `vi.stubGlobal("crypto", { getRandomValues: real.getRandomValues.bind(real) })` (a typed `(values: Uint8Array)` wrapper fails `tsc`), `vi.unstubAllGlobals()` in `afterEach`; a UUID builder is pinned by filling the bytes with 0x00 and 0xff, which shows the version and variant bits and the 8-4-4-4-12 layout.
- A mutation that survives once is a missing guard, not a nuisance: two web survivors (a reason text shown without a blocked button; the page-size argument of the pager) each got a test and were killed on the rerun. `useQueries` callers that de-duplicate ids by hand are an equivalent mutant, because react-query already collapses equal keys. A flags-by-role matrix test (kinds times readers, collecting every deviation into one `wrong` list, with `missing` printed for an absent field) names the absent field on the pre-fix copy at once.
