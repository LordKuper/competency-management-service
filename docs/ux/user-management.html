UX-спецификация — Управление пользователями (user-management)

3 flows · 4 mockups · updated 2026-10-07

Сценарии

UI подсистемы: вход и выход (AC-6), собственный пароль (AC-7) и раздел «Пользователи» для глобального администратора (AC-7, AC-8, AC-13). Раздел и его окна доступны только администратору; остальным адрес раздела показывает «Страницу не найдена» (app-shell.html), а API отклоняет запросы кодом 403.

Notes: экран вне рамки приложения, на surface-page, карточка по центру (на десктопе около четверти ширины, на узком экране почти вся ширина). Фокус при открытии — в поле e-mail. Поля e-mail и пароль обязательны; пустое поле даёт сообщение под полем, сервер добавляет собственные сообщения по полям. Проверка формата e-mail браузером отключена, чтобы пользователь видел русский текст сервера. Отказ показывается одним и тем же предупреждением независимо от причины (неверный пароль, нет такой записи, блокировка); при частых ошибках сервер вводит временную блокировку (lockout), и пользователь видит просьбу подождать. Кнопка «Войти» — единственное главное действие, крупная, на всю ширину. Текст-подзаголовок «Компетенции и карьерный рост» — text-secondary.

Измените условия поиска или создайте нового пользователя.»; таблица прокручивается по горизонтали, если не помещается.

Notes:

  • Одно окно для создания и правки. Правка сначала читает актуальную запись (пока идёт запрос — заглушка загрузки; при ошибке — предупреждение «Не удалось загрузить пользователя» с кнопкой «Повторить»), и сохранение отправляет версию именно этой записи. Пароль есть только в окне создания; пароль существующей записи меняется через «Сбросить пароль».
  • Поле «Сотрудник» доступно для обеих ролей. Привязка необязательна для любой роли, в том числе для глобального администратора (AC-8; прежнее решение «поле заблокировано для администратора» отменено). Выбор — поиск по ФИО среди работающих сотрудников, в списке видны подразделение и должность (различать однофамильцев); привязка очищается крестиком. Сервер отказывает, если сотрудник уже привязан к другой учётной записи или уволен; причина показывается предупреждением в окне.
  • Ошибки. 409 по полю (занятый e-mail) показывается только под полем, второй раз — в предупреждении — нет; прочие отказы показываются предупреждением в верху окна. Если запись изменили другие (412), пользователь видит «Данные изменены другим пользователем…», форма пересобирается на актуальных данных. До такого отказа фоновое обновление кэша введённое пользователем не затирает.
  • Успех. Всплывающее сообщение «Пользователь создан» или «Изменения сохранены»; окно закрывается; список пользователей и оргструктура (в карточках сотрудников виден e-mail учётной записи) перечитываются.
  • Поле e-mail — type=email без проверки браузером; формат проверяет сервер и возвращает русское сообщение.

Notes:

  • Блокировка — подтверждение с красной кнопкой-глаголом «Заблокировать»; «Разблокировать» — обычная синяя кнопка, текст «Пользователь снова сможет войти в систему.» Результат — всплывающее сообщение. Отказ сервера (например, нельзя заблокировать последнего активного администратора или разблокировать привязанную к уволенному сотруднику запись) показывается всплывающим сообщением с причиной; окно подтверждения к этому моменту закрыто.
  • Сброс пароля: после успеха сообщение «Пароль сброшен», все сессии пользователя завершаются. Форма сбрасывается при каждом открытии.
  • Смена собственного пароля: три поля; «Повторите новый пароль» сравнивается на клиенте («Пароли не совпадают»); ошибки сервера (например, неверный текущий пароль) показываются под соответствующими полями или предупреждением в окне. Успех — «Пароль изменён».
  • Кнопки в формах: главное действие слева в цвете primary, «Отмена» рядом; в окнах подтверждения «Отмена» слева, подтверждение справа. Во время сохранения кнопка занята и не нажимается повторно.

Паттерны взаимодействия

  • Все изменения учётных записей — в модальных окнах из меню строки (решение пользователя, волна 17); отдельных страниц создания и правки нет.
  • Меню «⋮» — единый способ строчных действий для пользователей, подразделений и сотрудников; разрушающее действие — красный пункт, отделяемый разделителем, если пунктов больше.
  • Подтверждение блокировки называет объект (e-mail), последствие и обратимость; безопасная кнопка — «Отмена». Блокировка завершает действующие сессии.
  • Конфликт версий (412): пользователь видит понятное сообщение и актуальные данные, форма пересобирается на них; фоновое обновление до отказа ввод не затирает.
  • Обязательность полей обозначена текстом сообщения под полем («Введите e-mail»), а не только цветом рамки: красная рамка всегда сопровождается значком и текстом.
  • Пароли. Подсказка о правилах пароля не называет длину (это настройка развёртывания): сервер сообщает, чего не хватает.
  • Тексты ошибок общие для приложения — в app-shell.html.
