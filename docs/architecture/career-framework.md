# Карьерная модель (`career-framework`)

## Purpose

Справочники карьерной модели — профессиональные направления, карьерные треки с упорядоченными карьерными уровнями, категории компетенций, каталог компетенций с историей версий, шкалы — и версионируемые матрицы компетенций подразделений с фиксированным маршрутом согласования (руководитель вышестоящего подразделения, затем ответственный HR) и публикацией; здесь же закрепление HR за подразделениями и вычисление ролей процесса «руководитель подразделения» и «ответственный HR». «Карьерный уровень» — уровень трека (`CareerLevel`, `/api/v1/career/levels`), с должностью сотрудника из справочника `org-structure` (`Position`, `/api/v1/positions`) он не связан. Модуль ссылается на `Competency.Platform`, `org-structure` (порт `IEmployeeDirectory`) и `user-management` (порт `IUserDirectory`), обратных ссылок нет; в журнал пишет через `[Audited]` и `IAuditWriter` из Platform (события — `audit.md`).

## Key paths

- `src/Competency.CareerFramework/`: корень модуля; типы `internal`, наружу выходят только `AddCareerFrameworkModule` и `MapCareerFrameworkEndpoints`, опубликованных портов нет; хост регистрирует модуль после `OrgStructure` и `UserManagement`. Все endpoints — под `/api/v1/career/…`.
- `src/Competency.CareerFramework/CareerFrameworkEntityConfiguration.cs`: таблицы `org_unit_hr`, `career_directions`, `career_tracks`, `career_levels`, `competency_categories`, `competencies`, `competency_versions`, `competency_scales`, `competency_matrices`, `matrix_versions`, `matrix_version_variants`, `matrix_version_decisions`; статусы и типы хранятся именами под CHECK; внешние ключи без каскадов (`ON DELETE RESTRICT`), на `org_units` и `users` — по имени сущности другого модуля. Страховочные уникальные индексы: один HR на подразделение (ключ `org_unit_hr`), одна матрица на пару «подразделение — трек», номер уровня в треке, одна опубликованная (`ux_matrix_versions_published`) и одна версия в работе (`ux_matrix_versions_in_work`) у матрицы, одна шкала по умолчанию (`ux_competency_scales_default`). Уникальный индекс проверяется на каждой строке сразу (`tech-reference/sql-postgresql-18.6.md`), поэтому публикация архивирует прежнюю версию отдельным `SaveChanges`, а перестановка уровней (`CatalogStore.MoveLevelsAsync`) сначала уводит номера перемещаемых уровней в отрицательные и сохраняет каждый отдельно.
- `src/Competency.CareerFramework/ProcessRoles.cs`, `ProcessRoleEndpoints.cs`, `CatalogViewer.cs`: роли процесса вычисляются в момент запроса из оргструктуры (`IEmployeeDirectory`: руководители, предки, поддеревья), учётных записей (`IUserDirectory`; участвует только учётная запись, которая может действовать, — `UserStatus.IsActive`) и закреплений HR и нигде не хранятся, поэтому смена руководителя или HR действует сразу; неактивные подразделения в ролях не участвуют. Кто действует на основании ролей, держит блокировку дерева (разделяемую или эксклюзивную) до фиксации. `CatalogViewer` — права пользователя в справочниках на один запрос. `GET /api/v1/career/me` отдаёт роли SPA для меню и действий; сервер проверяет права при каждом действии заново.
- `src/Competency.CareerFramework/OrgUnitHr.cs`, `OrgUnitHrEndpoints.cs`: `/api/v1/career/org-units/{id}/hr` — закреплённый HR подразделения и унаследованный от ближайшего вышестоящего с закреплением. Чтение — любой аутентифицированный (признак `isActive` учётной записи — только администратору); закрепление (`PUT`) и снятие (`DELETE`, удаление строки) — `GlobalAdmin`, без `If-Match`, под эксклюзивной блокировкой дерева (`IEmployeeDirectory.BeginExclusiveAsync`; её же берёт блокировка учётной записи), закрепить можно только учётную запись, которая может действовать.
- `src/Competency.CareerFramework/CatalogEntry.cs`, `CatalogEndpoints.cs`, `CatalogStore.cs`, `CatalogListQuery.cs`: общая модель шести справочников (направление, трек, уровень, категория, компетенция, шкала) — статус `Draft` / `Active` / `Inactive`, автор, `Version`; подразделение (`owner_org_unit_id`) есть только у трека, уровень принадлежит треку. Общие шаги endpoints: недоступное для чтения — 404, изменение видимого без прав — 403; изменение — под `CatalogStore.BeginWriteAsync` (порядок блокировок — `stack.html`) и с `If-Match`, кроме создания; дубль названия — 409 с ошибкой поля (`Rejection.Taken`), область уникальности учитывает черновики автора и проверяется заново при утверждении черновика (`POST …/{id}/approve`); ответы записей несут `canEdit` и `canDelete`; списки — серверные страницы, поиск `q` и фильтры (`CatalogListQuery`, пределы — `ListRequest`), `inWork=true` исключает неактивные записи для выпадающих списков с поиском по вводу.
- Endpoints справочников: `CareerDirectionEndpoints.cs` (`/api/v1/career/directions`), `CareerTrackEndpoints.cs` (`/tracks`; `PUT /tracks/{id}/level-order` — порядок уровней, `If-Match` трека), `CareerLevelEndpoints.cs` (`/levels`, права — по треку), `CompetencyCategoryEndpoints.cs` (`/categories`), `CompetencyEndpoints.cs` (`/competencies`; каждое изменение добавляет строку `competency_versions`, история — `GET …/{id}/versions`; без `scaleId` — шкала по умолчанию), `CompetencyScaleEndpoints.cs` (`/scales`; баллы — `jsonb` на строке шкалы; `POST …/{id}/make-default`; шкала, использованная опубликованной версией матрицы, не меняется — 409, проверку и публикацию разделяет блокировка справочников), `CatalogDraftEndpoints.cs` (`/drafts` — черновики, ожидающие утверждения текущим пользователем).
- `src/Competency.CareerFramework/MatrixVersion.cs`, `MatrixContent.cs`, `MatrixVariant.cs`, `MatrixDecision.cs`, `MatrixEntries.cs`: содержимое версии (уровни с порогами, блоки, компетенции, коэффициенты блоков, требования) — один `jsonb`-документ на строке `matrix_versions`, поэтому любая правка меняет `Version` строки и защищена `If-Match`; варианты автора и согласующего — копии документа (`matrix_version_variants`), правки согласующего — разница двух копий; решения (`matrix_version_decisions`) только добавляются. При публикации в `snapshot` пишутся названия и поля уровней, компетенций и шкалы на этот момент; опубликованная и архивная версии читаются только из снимка. Документ в журнал не пишется. Отображение `jsonb` — `tech-reference/npgsql-entityframeworkcore-postgresql-10.0.3.md`.
- `src/Competency.CareerFramework/MatrixWorkflow.cs`, `MatrixRoute.cs`, `MatrixCatalog.cs`, `MatrixEndpoints.cs`, `MatrixVersionEndpoints.cs`, `MatrixApprovalEndpoints.cs`: `/api/v1/career/matrices` (матрицы, их версии, создание новой версии копией опубликованной), `/api/v1/career/matrix-versions/{id}` (чтение, `PUT …/content`, `submit`, `approve`, `return`, `accept-changes`, `accept-and-revise`, `rollback-changes`, история, варианты и их разница), `/api/v1/career/approvals` (версии, ждущие согласования текущим пользователем). Статусы `Draft` → `OnReview` (→ `Returned`) → `Approved` → `Published` → `Archived`; маршрут и согласующий вычисляются в момент действия (`MatrixRoute`); полнота версии и допустимость её записей справочников проверяются при отправке, возврате с правками и принятии правок (`MatrixCatalog`). Блокировки переходов и правки содержимого — `stack.html` («Целостность на уровне данных»). Согласование HR публикует версию, архивирует прежнюю опубликованную и делает действующими черновые записи, которые версия использует. Ответ версии несёт `actions` — действия, доступные пользователю сейчас; строки списков матриц и черновиков несут `version` для `If-Match`.
- `src/Competency.CareerFramework/DeletionBlockers.cs`, `DeletionRefusal.cs`, `CatalogStore.cs` (`MatricesUsing`, `RemoveHistoryRow`): физическое удаление записей справочников и матриц без опубликованных версий (`DELETE`, `If-Match`; у матрицы — версии в работе, проверяется до удаления зависимых строк). Ссылки по столбцам держат внешние ключи `RESTRICT`, ссылки из `content` версий, их вариантов и `snapshot` — запрос `jsonb @>`. Отказ — 409 `DeletionRefusal`: `blockers` (до 5 мешающих записей, видимых пользователю: вид, id, название, контекст) и `moreCount` (остальные, невидимые включительно). Удаление строк истории (`competency_versions`, варианты, решения) журналирует `RemoveHistoryRow` (`audit.md`).
- `src/Competency.Platform/Migrations/` (общая линия миграций): `OrgUnitHr`, `CareerCatalogues` (начальные данные — общие категории компетенций и базовая шкала 0–4 с фиксированными Guid, без событий журнала), `CompetencyMatrices`, `CatalogOwnership`, `RemoveCareerLevelSalary`, `SimplifyCareerLevels`, `WidenMatrixDecisionKind`.
- `web/src/features/career/`: раздел SPA «Карьерная модель»; перетаскивание уровней трека — `TrackLevels.tsx` (`tech-reference/dnd-kit-6.3.1.md`).
- `docs/product/requirements/career-framework.html`: требования; `docs/ux/career-framework.html`: UX-спецификация.
