# Оргструктура (`org-structure`)

## Purpose

Строгое дерево подразделений (один родитель, без типов, физического удаления нет — только деактивация), общий справочник должностей с перечнем допустимых должностей у каждого подразделения и справочник сотрудников (ФИО тремя полями, подразделение, должность из справочника, статус «работает / не работает»); администратор изменяет, остальные читают урезанную проекцию. «Должность» — запись этого справочника (`Position`, `/api/v1/positions`), не карьерный уровень трека из `career-framework`. Модуль зависит только от `Competency.Platform`: журнал подключается через `[Audited]` и `IAuditWriter` из Platform, учётные записи — через порт `IEmployeeAccounts`, который объявляет здесь и реализует `user-management`, а находки рабочего стола модуль отдаёт через `IDeskSource` из Platform.

## Key paths

- `src/Competency.OrgStructure/`: корень модуля; типы `internal`, наружу выходят `AddOrgStructureModule`, `MapOrgStructureEndpoints` и два порта ниже.
- `src/Competency.OrgStructure/IEmployeeDirectory.cs`, `EmployeeDirectory.cs`, `EmployeeStatus.cs`, `OrgUnitStatus.cs`: порт чтения сотрудников и подразделений для других модулей: `FindAsync`, `FindManyAsync` — сотрудник (id, ФИО по частям, работает ли); `FindUnitAsync`, `FindUnitsAsync` — подразделение (id, название, `parentId`, `headEmployeeId`, активно ли); `FindAncestryAsync` — само подразделение и его предки до корня, от ближайшего; `FindSubtreeAsync` — подразделение и все ниже него; `FindHeadedUnitsAsync` — подразделения, которыми руководит сотрудник (их может быть несколько в любой части дерева; активность фильтрует вызывающий); `BeginExclusiveAsync` и `BeginSharedAsync` — транзакция под блокировкой дерева в эксклюзивном или разделяемом режиме; `FindOrgSnapshotAsync` — снимок оргструктуры одним вызовом: все подразделения (id, родитель, руководитель, активность), собственные перечни должностей подразделений, должности (название, активность) и число работающих сотрудников по паре «подразделение — должность». Запись `OrgSnapshot` несёт методы-правила владельца — предки, поддерево, «доступные подразделению должности» (свой перечень и перечни предков); вызывающий эти правила не повторяет. Записи `EmployeeStatus` несут `OrgUnitId` и `PositionId`. Реализация scoped, на том же `AppDbContext`, что и запрос, и запоминает снимок на время запроса, поэтому источники стола и экраны сценариев читают его один раз. Снимок читает всю оргструктуру: для 10 000 сотрудников это приемлемо, при росте на порядок нужна загрузка по поддереву. Читают порт `user-management` и `career-framework`; прямых запросов к таблицам модуля у них нет.
- Источник стола (внутренний класс `IDeskSource`, регистрируется в `AddOrgStructureModule`), только администратору: действующее подразделение без руководителя, должность работающего сотрудника вне доступного подразделению перечня, пустой перечень должностей у подразделения с сотрудниками, неактивная должность у работающих сотрудников (справочно), неиспользуемая должность (справочно), пустое подразделение — без сотрудников и дочерних (справочно; поглощает «без руководителя»: руководитель — работающий сотрудник подразделения, поэтому пустое подразделение всегда без руководителя). Данные — наборными запросами по своим таблицам. Предпосылки стола `ActiveUnit`, `ActivePosition` и `WorkingEmployee` (`desk.md`) источник отдаёт каждому вошедшему, не только администратору, по тому же снимку (`WorkingEmployee` — непустое число работающих сотрудников по парам «подразделение — должность»): дерево, справочник должностей и работающих сотрудников читает любой вошедший, поэтому факт ничего не раскрывает.
- `src/Competency.OrgStructure/IEmployeeAccounts.cs`: порт, который объявляет модуль и реализует `user-management` (`EmployeeAccounts`): `BlockAsync(employeeId, unbind)`, `LockAdministratorsAsync`, `IsLastActiveAdministratorAsync`. Реализация только помечает изменения на общем контексте; сохраняет вызывающий, в своей транзакции.
- `src/Competency.OrgStructure/EmployeeAccount.cs`, `OrgStructureEntityConfiguration.cs`: keyless-запрос (`ToSqlQuery`) по таблице `users` — e-mail и признак блокировки привязанной учётной записи для ответов о сотруднике и для `impact`; единственное обращение к данным другого модуля, только чтение.
- `src/Competency.OrgStructure/OrgTree.cs`: дерево хранится списком смежности (`parent_id`); поддерево и путь — `WITH RECURSIVE … UNION` через `FromSql`. Цепочка предков — `WITH RECURSIVE … ORDER BY depth` с защитой `CYCLE`. **Блокировка дерева** — `pg_advisory_xact_lock(5001001)`, эксклюзивная у всех изменений подразделений, сотрудников, справочника должностей, перечней подразделений и закреплений HR и у изменений учётных записей, зависящих от сотрудника; разделяемая (`pg_advisory_xact_lock_shared(5001001)`, `BeginSharedAsync`) — у действий, права на которые выводятся из дерева, но дерево не меняющих (`career-framework`); разделяемую не повышают до эксклюзивной в той же транзакции. Берётся первой (единый порядок блокировок — `stack.html`, «Целостность на уровне данных»). Одна блокировка на всё дерево рассчитана на редкие правки администратора; при конкуренции — блокировка по поддереву. Нужна изоляция read committed по умолчанию.
- `src/Competency.OrgStructure/OrgUnitEndpoints.cs`: `/api/v1/org-units`. Чтение (дерево, список, поддерево, путь, сводка) — любой аутентифицированный; изменение (создание, правка, перенос, деактивация, активация) — `GlobalAdmin`, с `If-Match`, под блокировкой дерева. Перенос в себя или потомка — 409; деактивация при активных дочерних подразделениях или работающих сотрудниках — 409; руководителем может быть только работающий сотрудник этого же подразделения (400, проверяется при смене руководителя, прежние несоответствия данных молча не исправляются). `GET /org-units/tree` отдаёт плоский список узлов с именем руководителя и числом сотрудников одним запросом (без N+1); клиент собирает дерево по `parentId`.
- `src/Competency.OrgStructure/EmployeeEndpoints.cs`, `EmployeeImpact.cs`: `/api/v1/employees`. Чтение — любой аутентифицированный (работающие сотрудники, ФИО, подразделение, должность — `positionId` и название, e-mail учётной записи; полная проекция со статусом и версией — только администратор); остальное — `GlobalAdmin`, с `If-Match`, под блокировкой дерева. При создании и изменении `positionId` должен указывать активную должность из перечня подразделения сотрудника или его предков (`Rejections.PositionProblemAsync`), иначе 400 с ошибкой поля `positionId`; если должность и подразделение не менялись, должность не перепроверяется. «Уволить» и «Удалить» каскадны в одной транзакции: сотрудник снимается с руководства всех подразделений, привязанная учётная запись блокируется (при удалении ещё и отвязывается), сессии обрываются; `GET /employees/{id}/impact` считает и применяет изменения одним кодом (`EmployeeImpact`), поэтому показанное подтверждение совпадает с выполненным. Увольнение и удаление сотрудника, к которому привязан последний активный администратор, — 409 под блокировкой администраторов. «Вернуть на работу» учётную запись не разблокирует. Перевод руководителя в другое подразделение снимает его с руководства прежнего в той же транзакции. Физически удаляется только сотрудник.
- `src/Competency.OrgStructure/OrgAccess.cs`: видимость по роли — администратор видит всё, остальные только активные подразделения и работающих сотрудников; недоступная запись для них — 404, мутация — 403, без сессии — 401 (прямой доступ по идентификатору проверяется на сервере, IDOR закрыт).
- `src/Competency.OrgStructure/TextSearch.cs` (общие шаги списков `ListQueries` и пределы `ListRequest` — в Platform): поиск `q` — `ILIKE` по подстроке (GIN `gin_trgm_ops`) или полнотекстовый `russian` по названию подразделения и должности и по ФИО и должности сотрудника; вектор сотрудника склеивается с вектором его должности в запросе (`||`, без GIN-индекса: generated-колонка не читает другую таблицу), поэтому один запрос может смешивать слова ФИО и должности; страницы 50 (по умолчанию) до 200, `q` не длиннее 200.
- `src/Competency.OrgStructure/Position.cs`, `PositionEndpoints.cs`, `PositionListQuery.cs`: `/api/v1/positions` — справочник должностей. Чтение — любой аутентифицированный (неактивные — только администратор), поиск `q` и фильтр активности; создание, переименование, деактивация, возврат в работу — `GlobalAdmin`, с `If-Match`, под эксклюзивной блокировкой дерева (под ней же проверяются перечни и должность сотрудника). Название обрезается и уникально без учёта регистра (`lower()` и в проверке, и в индексе), дубль — 409 с ошибкой поля (`Rejection.Taken`). Должность не удаляется, только деактивируется: занявшие её сотрудники, перечни и связи с уровнями треков (`career-framework`) её сохраняют. `GET …/{id}/impact` — число работающих сотрудников с должностью перед деактивацией.
- `src/Competency.OrgStructure/OrgUnitPosition.cs`, `OrgUnitPositionEndpoints.cs`: `/api/v1/org-units/{id}/positions` — собственный перечень подразделения и унаследованные от предков должности с подразделением-источником (чтение — любой аутентифицированный). Добавление (только активной; повторное ничего не меняет) и исключение — `GlobalAdmin`, под эксклюзивной блокировкой дерева; исключение удаляет строку перечня (события — `audit.md`), сотрудники должность сохраняют; `GET …/{positionId}/impact` — число работающих сотрудников поддерева с этой должностью. `POST …/quick-add` — в одной транзакции находит должность по названию без учёта регистра (неактивную возвращает в работу) или создаёт её и добавляет в перечень, для формы сотрудника.
- `src/Competency.Platform/Migrations/` (общая линия миграций, одна `InitialCreate` — `stack.html`, «Контракт из кода»): таблицы `org_units`, `employees`, `positions` (уникальный индекс `IX_positions_name_lower` по `lower(name)` — SQL-командой в `InitialCreate`, модель его не выражает), `org_unit_positions` (составной ключ `org_unit_id`, `position_id`); `employees.position_id` — NOT NULL, внешний ключ на `positions`; `full_name` — stored generated колонка из трёх частей имени (в журнал попадают только части); `search_vector` — generated `tsvector`; внешние ключи без каскадов (`ON DELETE RESTRICT`); расширение `pg_trgm` создаёт миграция.
- `docs/product/requirements/org-structure.html`: требования; `docs/ux/org-structure.html`: UX-спецификация.
